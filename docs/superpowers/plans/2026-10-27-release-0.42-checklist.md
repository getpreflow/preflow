# Release 0.42 checklist

Data integrity for the flow editor and games (BG Genius step 3): saving `null` clears an SQL column,
unique fields (validated, the database is the guard), typed record tables and a one-time conversion
script for existing sites. Spec `docs/superpowers/specs/2026-10-27-data-integrity-design.md`, plan
`docs/superpowers/plans/2026-10-27-data-integrity.md`.

The work is on `feat/data-integrity`. The release is prepared (READMEs, roadmap, this list). It is not
merged, pushed, tagged or deployed; the owner decides.

- **preflow/data:**
  - `PdoDriver::save()` writes nulls and never replaces a row: SQLite upserts on the primary key
    (`INSERT … ON CONFLICT(id) DO UPDATE`), MySQL runs `UPDATE`, then `INSERT` for a new record (a
    lost race on the primary key retries the update once). A partial save leaves other columns alone.
  - `Dialect` gains `updateSql()`, `isPrimaryKeyViolation()` and `uniqueViolation()`; `upsertSql()`
    returns `?string` (null on MySQL). `Preflow\Data\UniqueViolation` (a `PDOException`) names the
    index or the columns.
  - Field options `unique` (`true` or a list of scope fields), `index`, `length` (JSON model files,
    `#[Field(unique:, index:, length:)]`); `Schema\ColumnKind` (text, short, number, boolean, date),
    `FieldKinds::column()`, `columnKindOf()`, `lengthRules()`; `Validation\Unique` rule;
    `DataManager::validateUnique()`, public `storageValues()` (empty to null for number, yes/no, date
    and unique fields); `ExclusiveWrites::exclusive()` (MySQL `GET_LOCK`, SQLite `BEGIN IMMEDIATE`, JSON
    `.lock`).
  - Typed record tables: `RecordTableSync::sync($def, $extra, $typed, $unique)` and `syncAll()`,
    `Schema\ColumnSpec`, `RecordTables` registry (bound by `Application::bootDataLayer`), grammar
    `recordColumnType()`, `createRecordIndex()`, `indexName()`; `RecordTableSync::specs()` is public.
    Sync only creates: it never alters an existing column and never adds a unique index to an
    existing column; it prints a drift warning instead.
  - `validation.unique` in en/de/fr (the validation package ships the texts).
- **preflow/folio:** field types implement `HasColumnKind`; unique, index and length in model JSON;
  `RecordValidator` adds the length rules; `Publisher::saveDraft()` checks unique fields and the form
  re-renders with 422 (before, a draft with a taken slug was a 500); `__published` snapshots get
  plain indexes; the `Importer` stores empty number, yes/no and date values as null; `TableSync`
  registers with `RecordTables`.
- **preflow/codes:** `code` is unique within `purpose`, `recipient` is indexed (length 320);
  `issue()` draws again (up to 3 times) on a taken code; raw use counting casts `max_uses` on MySQL.
- **preflow/members:** `email` is unique (length 320); `register()` maps a racing duplicate to
  `EmailTakenException`.
- **preflow/media, codes, members, Folio:** register their tables with `RecordTables`.
- **tools/convert-typed-columns.php** (monorepo, not a package): see below.

Constraints (the packages' `ComposerConstraintsTest` pins them):

- `preflow/codes`, `preflow/members`, `preflow/media`, `preflow/folio`: require `preflow/data`
  `^0.42 || @dev` and conflict with `preflow/data` `<0.42`.
- `preflow/codes`: requires `preflow/validation` `^0.26 || @dev` (a taken code raises
  `Preflow\Validation\ValidationException`; `Codes` catches it).
- `preflow/data`: requires `preflow/validation` `^0.42 || @dev` and conflicts with it `<0.42` (the `validation.unique` text).
- `composer.lock`: refresh the path packages on `main` after the merge.

## Upgrading to 0.42: notes for site owners

- **`composer update 'preflow/*'`, then `preflow migrate`** (in the deploy). Migrate stays additive: it
  creates missing tables, adds missing columns (typed) and the indexes of those new columns. It never
  alters an existing column and never adds a unique index to an existing column.
- **Existing tables keep their text columns** until the site is converted. Until then every
  `preflow migrate` (and `folio:extensions:apply`) prints drift warnings
  (`warning: code.max_uses is text, expected number; convert the table (see the data README)`).
  They are harmless; the unique guarantees for members `email` and codes `code` only hold after the
  conversion adds the unique indexes (validation checks them before).
- **Partial saves no longer null other columns on SQLite** (`INSERT OR REPLACE` is gone). A save
  with only some keys keeps the other columns.
- **Saving `null` clears the column** on MySQL as well (it kept the old value before); sites that
  cleared with `''` can keep doing so. A `null` into a `NOT NULL` column of a migration-made table
  now fails instead of keeping the old value.
- **Unique `members.email` and `codes.code` (within `purpose`).** A site with duplicates sees them in
  the script's `--check`; resolve them first, nothing is converted until the check is clean.
- **Empty values in a unique field are stored as `NULL`** (the unique index would refuse a second
  `''`). A `Model` property for a unique field must accept `null`; a `string` property keeps `''` and
  a second empty value reports "already taken".
- **Unique checks and their errors:** a duplicate is a `ValidationException` on the field
  (`validation.unique`), with or without validation: a save with `validate: false` can throw it too,
  when the database's unique index refuses the write. Callers of `save()` for unique types should
  expect it. Unique checks on JSON storage and on translatable unique fields scan every record of the
  type (under the type's lock).
- **Empty strings in number, yes/no and date columns are stored as `NULL`** (saves and the Folio
  importer); empty text stays `''`.
- **Custom code:** `Dialect` implementations add `updateSql()`, `isPrimaryKeyViolation()`,
  `uniqueViolation()`, and `upsertSql()` returns `?string`; `SchemaGrammar::createRecordTable()`
  takes `list<ColumnSpec>`; raw SQL comparing a typed column to `''` fails on typed MySQL columns
  (`CAST(col AS CHAR)`, as codes does). `RecordTableSync::specs()` is public.
- **New texts:** `validation.unique` (en/de/fr, German "Sie").

### Converting a site: the order

The script is not a package and not a command: it lives in `tools/` of this repository and runs
against a site directory with that site's own vendor (data 0.42 or newer).

1. Locally, on a copy: `php tools/convert-typed-columns.php <site> --sqlite=<copy> --check` (SQLite) or
   `--check` against a restored dump (MySQL). Fix whatever it lists (table, record id, field, value,
   reason); it changes nothing.
2. Deploy the release. `preflow migrate` runs in the deploy and stays additive.
3. On the live site, with the owner's go-ahead: upload the whole `tools/` directory (the script and
   `tools/Convert/`), run the script in maintenance (no writes during the run: yes/no values are
   mapped while converting and a restore loses later writes), check the output, remove `tools/`.
   The script backs up to `storage/backups/` first (beside the copy with `--sqlite`, or
   `--backup-dir`); nothing rotates the backups, so they accumulate: delete old ones by hand once a
   conversion is verified. Long SSH jobs are killed after about 12 minutes: it
   converts table by table and a rerun continues.
4. Restore, if needed: SQLite, copy the backup file back over the database; MySQL, `mysql < dump`.

Per site:

- **smeyer.me:** JSON storage only, nothing to convert.
- **smart-stack.works:** SQLite. Steps 1 to 4 as above (`code` and `member`, 1 and 3 rows today).
- **holz-objekte.org:** MySQL, converts in its own session.
