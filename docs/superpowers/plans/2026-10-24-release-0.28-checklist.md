Relations, `onDelete`, `whereAny`, `searchLoose`, the JSON storage cache and delete plans in
`preflow/data` (Part 1 of the folio-lists work). The work is on `feat/folio-lists`, branched
from `e7e6b94`. The release is prepared: the data README, the roadmap entry and the core

## Release (framework)

- [ ] **Owner's go-ahead**, and whether 0.28.0 goes out alone or together with 0.29.0.
- [ ] **Merge.** Fast-forward `feat/folio-lists` into `main`. Run the site suites first:
  smart-stack.works, smeyer.me and holz-objekte.org (the last needs its path repo / symlinks
  to see the branch).
- [ ] **Push `main`.**
- [ ] **Tag** `v0.28.0` with the message
  `v0.28.0: relations and onDelete, whereAny, searchLoose, JSON storage cache, delete plans`
  and push the tag. CI splits the packages. Push the tag after the main split has finished
  (see the 0.27 ref race).
- [ ] **Split workflow** succeeded.
- [ ] **Packagist** shows v0.28.0 for `preflow/data` and `preflow/core`.
- [x] **Constraints** (already in the branch). `^0.27 || @dev` in `require` matches any
  version, so the guard is a `conflict` entry:
  - `preflow/core` conflicts with `preflow/data` `<0.28` (was `<0.25`): `Application` passes
    `cacheDir:` to `JsonFileDriver`, which an older driver ignores silently (no cache).

  No other package calls the new data APIs yet; Folio's bound follows in 0.29.0.

## Sites (after the tag)

- [ ] **smart-stack.works, smeyer.me, holz-objekte.org:** `composer update 'preflow/*'`, then
  run the suite. JSON-stored types now cache under `storage/cache/data` (must be writable; if
  not, queries still work, uncached).

## Notes

- `search()` is unchanged. `Field::searchable` and the type definition's `searchable` are now
  nullable (unset = include in `searchLoose()`, still excluded from `search()`).
- SQLite `LIKE` folds case for ASCII only; MySQL `IN` / `CONTAINS` follow the column collation.
- JSON-file writes of a delete plan are not rolled back; a plan is a snapshot.
