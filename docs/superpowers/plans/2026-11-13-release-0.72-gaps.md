# Release 0.72 — gaps the starters fill Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The four gaps the starters and sites fill with copied app code move into the framework, and the copies go (spec D9); the 0.71 aliases go.

**Architecture:** data creates declared indexes on existing tables too and takes composite indexes; view's SEO prints the chosen description; data gets a unique-slug helper on `Slug::clean()`; route middleware takes arguments; a generic safe return-path check lives in core and members' `SafeNext` uses it. The starters drop their copies; the sites drop theirs where the framework now covers them.

**Tech Stack:** PHP 8.4, PHPUnit 11, the Preflow monorepo; the six sites.

**Spec:** `docs/superpowers/specs/2026-11-12-package-audit-fixes-design.md` (D9). Evidence: `.superpowers/audit-2026-11-12/report-folio-ui-starters.md` (STARTERS-3 to 6).

## Global Constraints

- Owner's rules: no workarounds; framework = abstractions only; Folio is the UI adapter.
- Stored data keeps its shape. Index names stay `RecordIndexNames` (`idx_<table>_<field>`); a composite index is `idx_<table>_<field1>_<field2>…` (shortened by the grammar's existing name rule if too long).
- Moved public classes keep aliases for one release; the 0.71 aliases are removed now.
- The six sites behave the same unless a release note says otherwise (the slug transliteration change below applies to new slugs only).
- Tests per package; full suite, mysql and starters at the release; never two test runs at once.

## Review Focus

1. A site whose `jobs` table already exists (made before 0.72) gets the declared `company` index on the next `preflow migrate`, on SQLite and MySQL, including the `__published` shadow table; a second migrate is a no-op. → Task 1 tests.
2. A declared index on an existing MySQL TEXT column gets a prefix length instead of failing. → Task 1 mysql test.
3. A page with an SEO description and a layout that already prints `<meta name="description">` does not get it twice. → Task 2 test.
4. `?next=//evil.example`, `?next=/%2F%2Fevil.example`, `?next=/a/../b`, `?next=\evil` are refused by the core check in every caller (members, starters). → Task 4 tests.
5. An existing slug is never changed by an upgrade: the helper is only called on create. → Task 3 test (update keeps the slug).

### Task 1: indexes — late and composite (data)

**Files:** `packages/data/src/Schema/RecordTableSync.php`, `TypeRegistry.php`, `TypeDefinition.php`, `Attributes/` (new `Index`), the grammars; publishing's shadow tables.

**Interfaces:**
- A declared field index (`#[Field(index: true)]`, type JSON `"index": true`) is created when missing on every sync, not only with a new column (`RecordTableSync.php:107-113`: drop the `in_array($field, $created)` condition; existing-index check by name stays). Same for a unique index (`:94-104`) **only when the column holds no duplicates**; otherwise the existing warning stays.
- Composite indexes: class attribute `#[Preflow\Data\Attributes\Index('state', 'updated_at')]` (repeatable) and type JSON `"indexes": [["state", "updated_at"]]` → `TypeDefinition::$indexes` (`list<list<string>>`); unknown fields refused at definition time.
- MySQL: an index on a TEXT/BLOB column gets a prefix length (191) in `createRecordIndex`; SQLite unchanged.
- Shadow tables: the publishing tables (`__published`) get the type's declared indexes too (revisions don't).
- [ ] Tests: Review Focus 1 and 2; composite index on SQLite and MySQL; unknown field in `indexes` refused; second sync no-op; existing duplicates keep the unique warning.
- [ ] Commit `feat(data): declared indexes reach existing tables; composite indexes`.

### Task 3: unique slugs (data)

- `Preflow\Data\Slugs::unique(DataManager $data, string $type, string $text, string $field = 'slug', ?string $exceptId = null, int $max = 80, string $fallback = 'item'): string` — `$type` is a type key or model class; base is `Slug::clean($text)` cut to `$max` at a hyphen boundary, `$fallback` when empty; `-2`, `-3`… until free.
- `Slugs::among(string $text, array &$taken, int $max = 80, string $fallback = 'item'): string` for in-memory imports.
- [ ] Tests: collision suffixes, `$exceptId` keeps its own slug, umlauts (`Müller` → `mueller`), empty text, max length; Review Focus 5 at the starter level (Task 6).
- [ ] Commit `feat(data): unique slugs on Slug::clean()`.

### Task 4: middleware arguments and a safe return path (routing, core, auth, members)

- `Preflow\Routing\MiddlewareWith(string $class, mixed ...$args)` (named args) usable in `#[Middleware(...)]` and `#[Route(middleware: [...])]` next to plain class strings; core's Kernel builds it with `Container::make($class, $args)` (add named-parameter support to `make()` if missing, with tests). `#[Middleware(new MiddlewareWith(AuthMiddleware::class, guard: 'employers'))]`.
- `Preflow\Core\Http\SafeReturnPath::check(?string $next, list<string> $allowedPrefixes): ?string` — the path rules of members' `SafeNext` (`..`, `//`, `\`, control characters, percent-encoded to a fixed point; a path, never a URL); null when refused. Members' `SafeNext` keeps its API and uses it.
- [ ] Tests: Review Focus 4 at the core level and through members; middleware with a guard argument protects a route on the second guard; plain strings unchanged.
- [ ] Commit `feat: middleware arguments; SafeReturnPath in core`.
