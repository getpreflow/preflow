# Release 0.68 — mail in notify, neutral members, codes without a mailer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every package sends mail through one neutral mail layer in notify; members' pages and mails are neutral and replaceable and never name Folio; codes ships no mailer; owner decisions and code rules live in the package cores (spec D5, D6, D7-codes).

**Architecture:** notify gains `Preflow\Notify\Mail` (content value objects, a layout interface with a plain-PHP default and a template-based one, a `Mailer` that composes text + HTML and sends). members, Folio's staff mails and (in BG Genius) the invitation mail use it. members' page CSS moves into a replaceable block with neutral defaults; the sites that relied on the old look keep it in their own overrides. Decision and code rules move from Folio controllers into `Members` and `Codes`.

**Tech Stack:** PHP 8.4, PHPUnit 11, Twig (templates), the Preflow monorepo; site repos smart-stack.works, bggenius-preflow, holz-objekte.org (path repos except holz).

**Spec:** `docs/superpowers/specs/2026-11-12-package-audit-fixes-design.md` (D5, D6, D7 codes part). Evidence: `.superpowers/audit-2026-11-12/report-auth-rbac-members-notify.md` (F1–F8), `report-data-validation-form-codes.md` (CODES-1, CODES-3), `report-folio-src.md` (FOLIO-2, FOLIO-3).

## Global Constraints

- Owner's rules: no workarounds; the framework holds abstractions only; Folio is the UI adapter; mails never mention Folio in any way (owner, 2026-11-12).
- No package names another package's classes, keys or files except through an interface or registration hook (a package may implement or call a public interface of a package it requires).
- No site colour, token or wording in any package. Neutral defaults: mail accent `#1a1a1a`; page styles use custom properties with neutral fallbacks.
- notify keeps zero hard dependencies (`"require": {"php": ">=8.4"}`); the template layout needs `preflow/view` and is wired only when view is installed (`suggest`).
- A site's existing look and wording do not change: every site that relied on a package default gets that default in its own files in the same release (Tasks 8–9).
- Tests: `vendor/bin/phpunit --testsuite <Package> [--filter …]` from the repo root per task; full suite only at the release; never two test runs at once. Site tasks: the site's `composer test`.
- No subagents inside tasks. Commit per task.

## Review Focus

1. A site layout written for the old members/codes layout variables (`lang`, `subject`, `accent`, `paragraphs`, `action`) renders unchanged through the new mailer (smart-stack's `@mail/layout.twig`, holz's `@folio/mail/layout.twig`). → Task 1 test `test_template_layout_gets_the_old_variables`.
2. A subject or name with CR/LF never breaks a header; a URL in a paragraph is linked, other HTML escaped. → Task 1 tests.
3. The owner mail on a site without any `MemberLinks` binding: no link, and it names the command that decides. → Task 2 test.
4. `members:decide` on a member already declined, and Folio's decline of an accepted member: same rules, remember-me sessions end on decline either way. → Task 3 tests.
5. A readable code created in Folio without an expiry gets the purpose's `ttl`; an edit of a revoked code's expiry is refused. → Task 5 tests.

- Produces: `final class MailText { public static function oneLine(string $value): string; /** @return list<string> */ public static function paragraphs(string $text, string $accent): array; public static function absoluteUrl(string $pathOrUrl, string $appUrl): string; }` — `oneLine` collapses `[\p{Cc}\p{Cf}\x{2028}\x{2029}]+` to one space and trims; `paragraphs` escapes, links `https?://[^\s<]+` with `style="color:{accent}"`, keeps single line breaks (`nl2br`); `absoluteUrl` accepts a path (`/x`, not `//`, no backslash, no whitespace/control chars) made absolute with `$appUrl`, or an absolute http(s) URL with a host, else throws `\InvalidArgumentException('The link must be a path or an absolute http(s) URL.')`.
- Produces: `final class MailConfig { __construct(public string $accent = '#1a1a1a', public ?string $layout = null, public ?string $from = null) ; public static function fromArray(array $notifyMail): self }` — from `config/notify.php` key `mail`.
- Produces: `final class Mailer { __construct(Notifier $notifier, MailLayout $layout, MailConfig $config); public function compose(MailContent $content, string $to, ?string $from = null, ?string $template = null, ?string $accent = null): Email; public function send(MailContent $content, string $to, ?string $from = null, ?string $template = null, ?string $accent = null): SentMessage; public function sendLater(MailContent $content, string $to, ?\Closure $onFailure = null, ?string $from = null, ?string $template = null, ?string $accent = null): void }` — subject through `MailText::oneLine`; `from` falls back to `MailConfig::$from`, then the channel's own; `template` to `MailConfig::$layout`; `accent` to `MailConfig::$accent`.
- Core binds `MailLayout` to `TemplateMailLayout` when `Preflow\View\TemplateEngineInterface` is bound, else `BasicMailLayout`.
