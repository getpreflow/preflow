# Release 0.73 — Folio redesign, part 1: tokens, primitives, shell Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Folio's admin gets the redesign's token set, restyled primitives and the new shell (sidebar, topbar, editor rail), as handoff phases 0–3 describe.

**Architecture:** Server-rendered Twig, `admin.css` with one `light-dark()` token set, `admin.js` without a framework: unchanged. The `:root` block takes the handoff's `tokens.css`; components keep their class names and change their CSS; markup changes only where the handoff says **markup** (shell, user menu, rail, busy buttons). Later releases do lists and editors (0.74) and settings, library screens and the ink layer (0.75).

**Tech Stack:** Twig, CSS (`light-dark()`, `color-scheme`), vanilla JS (`admin.js`, tests in `packages/folio/tests/js` with `node --test`), PHP 8.4 / PHPUnit 11 for template tests.

**Spec:** the owner's handoff, extracted (git-ignored) at `.superpowers/folio-redesign/folio-redesign-handoff/`: `README.md` (intent, rules), `PLAN.md` (phases 0–3 here), `tokens.css`, `COMPONENTS.md` (§1–§3 primitives), `SCREENS.md` ("Shell"), `INK.md` (brand tile only here), `icons.md`, `reference/*.dc.html` (boards: Foundations, Library · actions / form fields / lists & feedback, Dashboard · light, Entry list · dark). Owner, 2026-11-13: implement as much and as far as possible; where design and implementation disagree, adapt and stay as close as possible; phase 8 proposals only after a yes.

## Global Constraints

- Handoff rules (README "Rules for the implementation"): keep the architecture (no build step, no Tailwind, no JS framework); keep class names where a component exists, new classes get the `folio-` prefix; keep every translation key, new UI text in `lang/en|de|fr/folio.php` (all three); accessibility as today or better (real buttons/links, `aria-label` on icon buttons, 4.5:1 text contrast, `prefers-reduced-motion` stops animations); tests after every task, template tests where a Twig structure changes.
- Not in this release (proposals, ask first): ⌘K search entry/palette, styled confirm, `/` block picker, crop previews, missing-alt filter, AI "Write a draft", recent-changes feed.
- Fonts: the token stacks name Inter and JetBrains Mono with system fallbacks. Self-hosting the woff2 files needs the owner's OK to download them; until then no `@font-face` and no font files (the system stack renders).
- Sign-in (`login.twig`, `_auth_*`) keeps its look; only its tokens switch.
- Every screen keeps working in light and dark, at 1440 px and 375 px (no horizontal page scroll at 375).
- Folio-only release: no other package changes.
- Tests: `vendor/bin/phpunit --testsuite Folio`, `node --test packages/folio/tests/js/`, `composer test:starters`; one test run at a time.

## Review Focus

1. A site that themes Folio through its own CSS custom properties (overriding `--c-accent` etc. in an extension stylesheet) still gets its colours: variable names stay, only values change. → Task 1 test that every variable admin.css and the other Folio stylesheets reference is defined in `:root`.
2. Keyboard and screen reader on the new user menu and rail: menu opens/closes with Enter/Escape, focus returns to the button, rail icons have `aria-label`. → Task 3 JS test + template test.
3. A site with many nav sections (holz-objekte) and saved collapsed state (`data-nav-save`) keeps that state after the shell change. → Task 3 JS test (nav-sections).
4. Dark mode with `[data-theme]` forced vs OS default: both pick the new values (no hard-coded colour left outside `:root` except the ink constants). → Task 1 test scanning admin.css for hex colours outside `:root`/ink.
5. The busy state never leaves a button disabled after an htmx error or a validation re-render. → Task 2 JS test.
