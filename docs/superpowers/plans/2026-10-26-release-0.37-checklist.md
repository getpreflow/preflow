# Release 0.37 checklist

Folio's admin in English, German and French. Every Folio screen, field type, list, message,
JS text and staff mail is behind translation keys; each staff user picks the admin language
(sidebar switch, account page), signed-out pages follow the browser, staff mails go out in the
recipient's language. A Translations screen lets admins change any admin text per language.
Model labels (types, fields, help texts, options, sections) take a map per language or
`site.*` keys. rbac, members (new `members-admin` group), codes and validation ship their
admin texts in the three languages. The capability lives in `preflow/i18n`: packages declare
their groups in `extra.preflow.translations` (scope `admin` or `public`), a translator boots on
every site, the fallback chain is user locale → site default → `en`, overrides are an
interface (`TranslationOverrides`), `Labels` and `DerivedKeys` resolve and collect model
labels, and `preflow translations:check` is the release gate. The work is on
`feat/folio-translations`. The release is prepared: i18n README, Folio README, glossary
(`docs/translations-glossary.md`), roadmap entry, spec, plan, constraints. It is not merged,
pushed or tagged; the owner decides.

Constraints (each conflict matches its require's lower bound; the packages'
`ComposerConstraintsTest` pins them):

- `preflow/folio`: data `^0.37` (`ModelLabelKeys`, label maps), i18n `^0.37` (scopes,
  overrides, `Labels`, `DerivedKeys`), validation `^0.37` (`Message`,

- `preflow/members`, `preflow/rbac`, `preflow/codes`: folio `^0.37`

  `^0.37`; conflicts `<0.37`. codes had no `conflict` block before.
- `preflow/validation`: i18n `^0.37`, conflict `<0.37` (new `conflict` block).
- `composer.lock` refreshed for the path packages only (`composer update preflow/validation
  preflow/codes preflow/folio preflow/members preflow/rbac`): their new requires, conflicts and
  declarations; no third-party package changed.

## Upgrading to 0.37: notes for site owners

Also in the i18n README and the Folio README. Put these in the release notes.

- **Packages declare their translations** in `composer.json` `extra.preflow.translations`
  (`{"group": {"path": "lang", "scope": "admin"|"public"}}`), read from
  `vendor/composer/installed.json` at boot. This replaces `$translator->addDefaults()` calls in
  providers (`addDefaultsIfMissing()` remains for apps without Composer metadata). Run
  `composer update 'preflow/*'` so `installed.json` carries the declarations and the
  `translations:check` command.
- **A translator boots without `lang/`.** Every site with `preflow/i18n` now gets a translator
  and the `t()`, `tc()`, `current_locale()`, `available_locales()` and `locale_url()` template
  helpers. The locale middleware still needs `lang/` or `config/i18n.php`, so the frontend of
  a site without either is unchanged. A site that registers its own `t` function would clash.
  A key missing in the site's locale but present in `en` now shows the English text instead
  of the raw key.
- **New tables:** `folio_user_preferences` (each user's admin language) and
  `folio_translation_overrides` (texts changed on the Translations screen). On SQL storage run
  `preflow migrate`; JSON storage needs nothing. The overrides travel with `folio:export` /
  `folio:import` / `folio:pull`; the users' language choices stay with each copy.
- **New permission `translations.edit`** for the Translations screen (Settings →
  Translations). An `admin` role with `*` has it; give it to other roles in rbac or
  `config/roles.php` as needed. Choosing one's own admin language needs no permission.
- **Validation's translator is opt-in.** Built-in rules now return a
  `Preflow\Validation\Message` (key plus parameters, `Stringable`) instead of a string; its
  English text is today's message. Site code that calls a built-in rule's `validate()`
  directly and expects a `string` must cast it (`(string) $result`) or call `->text()`.
  `Validator` and `ValidatorFactory` take an optional `Translator`; without one, messages
  stay English, so the site's own forms are unchanged. Folio passes the admin's translator
  for admin requests only. A site's `lang/{locale}/validation.php` only takes effect where a
  translator is passed.
- **members split:** the admin texts of `preflow/members` (member list, Decision panel,
  members settings, states, permissions) moved to the new `members-admin` group (scope
  `admin`). The public `members` group (member pages, mails to members, German "Sie") is
  unchanged. The admin texts were English literals before, so no site key moves; a site
  changes them in its own `lang/{locale}/members-admin.php` or on the Translations screen.
- **Standard German spelling in staff mails:** the invitation and password-reset mails use
  "Hallo {name}," and "Freundliche Grüße" (ß, comma), and all three languages gained a closing
  line. Mails to members are unchanged.
- **rbac's German switched from "Sie" to "du"**, like the rest of the admin. A site that
  overrode rbac texts should check its wording.
- **English output changes in the admin:** dates use `folio_date()` (revision and schedule
  times read "Oct 26, 2026 14:05" instead of "2026-10-26 14:05"; date filter chips "from Jan 1,
  2026"; codes' redemption times; date fields in list cells and read-only fields, and the
  members Decision panel's "Registered …", read "Oct 26, 2026" / "Oct 26, 2026 14:05" instead
  of "26 Oct 2026" / "26 Oct 2026, 14:05", and "26.10.2026" / "26/10/2026" in German and
  French), numbers are grouped ("12,345"), and "No :label yet." /
  "Search :label" lowercase only the first letter of the label. Tests that pin those strings
  need updating.
- **Sidebar:** Settings gains *Translations* (between Extensions and Cache) on every site.
  Tests that pin the sidebar need the entry.
- **Model labels may be maps:** `label`, `label_singular`, field `label`/`help` and select
  option labels take `{"en": …, "de": …}`; or add `site.types.{type}.label`,
  `site.fields.{type}.{field}.label`, `site.options.{type}.{field}.{value}` and
  `site.sections.{section}` to `lang/{locale}/site.php`. Plain strings work as before.
- **Extensions:** `#[FolioExtension(translations: 'group')]` names the extension's group; its
  types resolve labels under that group, and attribute labels (`#[ListColumn]`,
  `#[RecordAction]`, `#[FormPanel]`, `#[BulkAction]`) may be keys. Requires Folio 0.37.
- **Block labels may be keys:** `#[Block(label: 'site.blocks.hero.label', group: …,
  description: …)]` and `#[BlockField(label: …, help: …)]` show in the admin's language when
  they are keys delivered in `lang/{locale}/site.php`; plain strings are shown as before.

## Release (framework)

- [ ] **Owner's go-ahead.**
- [ ] **Merge.** Fast-forward `feat/folio-translations` into `main`. Run the site suites first.
- [ ] **Push `main`.**
- [ ] **Tag** `v0.37.0` with the message
  `v0.37.0: Folio admin in English, German and French — per-user language, Translations screen, translatable model labels`
  and push the tag. CI splits the packages.
- [ ] **Split workflow** succeeds.
- [ ] **Packagist** shows v0.37.0 for `preflow/i18n`, `preflow/folio`, `preflow/data`,
  `preflow/validation`, `preflow/members`, `preflow/rbac`, `preflow/codes` and `preflow/core`.
- [ ] **Constraints:** moved (see above).

## Sites (after the tag)

- [ ] **Raise the sites' `preflow/*` constraint** to `^0.37 || @dev` and run
  `composer update 'preflow/*'`, then the suite. Ship the bump, the lock and the deploy together.
  `php preflow translations:check` is listed once `installed.json` is refreshed.
- [ ] **`preflow migrate`** on SQL sites after deploy (the two new Folio tables).
- [ ] **smart-stack.works:** add `'Translations'` to the expected sidebar in
  `MembersGroundworkTest::test_sidebar_structure`; decide whether its `lang/{en,de}/members.php`
  keys need `fr` (only if the site offers French, or until the check skips site-only keys in
  languages the site doesn't offer).
- [ ] **Roles:** give `translations.edit` to the roles that should change admin texts.
- [ ] **holz-objekte.org (before it upgrades):** its staff are the reason for this release
  (German/French admin). It still needs `storage/media-versions` as a shared dir and the
  `AssetInUseException` handling noted in the 0.34 and 0.35 checklists. Not touched here.
