# Release 0.40 checklist

Codes for personal invitations. `preflow/codes` runs without Folio: the core defines the type `code`
itself (storage alias `codes`, else `default`) and Folio's richer definition takes its place when its
built-in `codes` extension is enabled. Folio carries the codes admin (`packages/folio/src/Codes/`,
translation group `codes`). New in codes: codes bound to a recipient (one use, `wrong_recipient`),
`forRecipient()`, `renew()`, a purpose `ttl`, `record()`/`get()`/`CodeRecord`, `CodeEvents`
(`codes.redeemed`, `codes.revoked`; a throwing redeemed listener undoes the use and the redemption),
and `CodeMailer` (invitation mail with a personal link; `mail.layout`, `mail.from`, `mail.accent`;
texts in `codes-mail`, German "Sie"). BG Genius's invitation route, welcome page, hosts and groups
stay app code (spec section 7, walked by `InvitationPathTest`).

The work is on `feat/codes-invitations`. The release is prepared: codes README, Folio README, roadmap
entry, spec (`docs/superpowers/specs/2026-10-27-codes-invitations-design.md`), plan
(`docs/superpowers/plans/2026-10-27-codes-invitations.md`). It is not merged, pushed or tagged; the
owner decides.

Constraints (the packages' `ComposerConstraintsTest` pins them):

- `preflow/codes`: no longer requires `preflow/folio`; requires core, data, i18n `^0.37`, notify
  `^0.25` and view `^0.1`.
- `preflow/folio`: suggests `preflow/codes`, conflicts with `preflow/codes` `<0.40` (an older codes
  package shipped its own admin extension).
- `composer.lock`: refresh the path packages on `main` after the merge
  (`composer update preflow/codes preflow/folio`).

## Upgrading to 0.40: notes for site owners

Also in the codes README. Put these in the release notes.

- **Providers order unchanged.** `CodesServiceProvider` stays where it is.
- **`config/folio/extensions.json` keeps `codes`.** The extension name, the type key `code`, the table
  `code`, the permissions (`code.*`, `codes.revoke`) and the field type `codes_purpose` stay. The
  admin class moved from the codes package into Folio; the cached extension list rebuilds by itself.
  Run `composer update 'preflow/*'` so Composer's `installed.json` no longer names
  `Preflow\Codes\Extension`.
- **The codes admin texts now come from Folio** (`packages/folio/lang`); the group name `codes` is
  unchanged, so a site's overrides keep working. The codes package ships only `codes-mail` (public).
- **The "alias `codes` required" error at boot is gone.** Codes fall back to the `default` storage.
  A site that has the alias keeps using it.
- **`preflow migrate` must run with the deploy** (in the same step) on every site that uses codes: it adds
  the columns `recipient` and `created_at` to the `code` table. Until then `issue()` fails on SQL
  (it writes `created_at`), and bound codes and `forRecipient()` fail too.
- **No index on `(recipient, purpose)`.** Folio syncs the columns as TEXT, which cannot be indexed
  without a length; `forRecipient()` scans by `recipient`. Fine for invitation volumes.
- **Moved classes:** `Preflow\Codes\Fields\PurposeFieldType` and `Preflow\Codes\Types\CodeAdmin` are now
  `Preflow\Folio\Codes\Fields\PurposeFieldType` and `Preflow\Folio\Codes\Types\CodeAdmin`. Site code that names them must change.
- **New conflicts in `preflow/codes`:** `preflow/core <0.38`, `preflow/data <0.38`, `preflow/folio <0.40`
  (guards, not requirements; members 0.38 did the same).
- **Compatibility:** `issue()`, `check()`, `redeem()`, `revoke()` and `redemptions()` keep their
  positional parameters; the new ones are appended and named.
- **New texts** in group `codes-mail` (en/de/fr, German "Sie").
- **holz-objekte.org:** run `preflow migrate` with the deploy (the `code` table gains `recipient` and `created_at`); no code change.
