# Release 0.76 — Folio redesign, part 3: settings, library, dashboard and ink Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The rest of Folio takes the redesign (handoff phases 6–7 and the dashboard): the ink layer, the dashboard, assets and asset detail, translations, redirects, cache and roles. Any data those screens need comes from public APIs in the packages that own it.

**Architecture:** This is the same approach as 0.73–0.75:

- server-rendered Twig;
- one `light-dark()` token set in `admin.css`;
- framework-free `admin.js`;
- no build step.

The new public APIs are small:

- in **media**: batch usage counts, a missing-alt query and the usage entry's type key;
- in **Folio's extension API**: a structured dashboard hook;
- in **Folio**: an ink-marks generator and a shared admin "not found" page.

Folio only reads these APIs and maps them to classes and tokens.

**Tech Stack:** Twig, CSS, vanilla JS (`node --test packages/folio/tests/js/`), PHP 8.4 / PHPUnit 11, htmx 2.0.11.

**Spec:** the owner's handoff at `.superpowers/folio-redesign/folio-redesign-handoff/` (git-ignored):

- `PLAN.md`, phases 6–7;
- `SCREENS.md`: Dashboard, Assets, Asset detail, Translations, Redirects, Cache, Role permissions and Sign-in;
- `INK.md`;
- `COMPONENTS.md`;
- `icons.md`;
- the boards `Dashboard`, `HolzDashboard`, `Assets`, `AssetDetail`, `Translations`, `Redirects`, `Cache`, `Roles`, `Ink` and `LibOverlays`.

Every row labelled **0.76** in `docs/superpowers/notes/2026-11-13-folio-redesign-deviations.md` is covered below. The current files, the data sources and the tests that pin today's markup, screen by screen, are in `docs/superpowers/notes/2026-11-14-folio-redesign-inventory-076.md`. ## Data rulings

| Question | Ruling | Why |
|---|---|---|
| "Used N×" on asset cards | **media**: `AssetUsage::counts(list<string> $assetIds): array<string, int>`, with an optional interface `Preflow\Media\Usage\CountsAssetUsage { public function usageCounts(list<string> $assetIds): array<string, int>; }`. A source that implements it answers for the whole page at once. Otherwise `counts()` falls back to `count(usagesOf($id))` for each asset of that source. Folio's `FolioRecordReferences` implements it: one query per type (the same LIKE match, all ids of the page OR-ed), counted in PHP. `CopyReferences` and `PosterReferences` implement it too. | A page of 50 cards would otherwise run 50 full usage scans. The batch path stays in the source that knows how to search. |
| "Missing alt text · N" | **media**: `MediaLibrary::query(..., ?bool $missingAlt = null)` (new last parameter): `true` keeps only images whose alt in the default locale is null or `''`. `MediaLibrary::missingAltCount(): int` counts the same set. | The SEO audit flags the default locale's alt. An image is the only kind an alt is asked for (`AssetCard` warns only on images today). |
| "Used in" with type icons | **media**: `AssetUsageEntry` gains `public ?string $type = null` (last constructor parameter), a key the source defines. `FolioRecordReferences` sets the type key it already has (`$listing->key`), and `CopyReferences` sets `'asset'`. Folio resolves the family, icon and label through `TypeCatalog`, with no family for an unknown key. | It is the same shape as `source`, a generic string with no Folio dependency. |
| Selection bar on Assets | **Move to bin**: `POST {prefix}/assets/bulk` with `_action=bin` and `ids[]`. Each asset goes through the same path as the single delete (usage refusal and bin rules). The answer is the grid with a flash that names the assets that were refused. **Edit alt text**: `GET {prefix}/assets/alt?ids[]=…` opens a drawer listing each selected image (thumb, name, alt input for the default locale), and `POST {prefix}/assets/alt` saves each one through the existing single-asset save. **Download** shows only when exactly one asset is selected (a link to `originalUrl()`). | Bulk download would need an archive format that no package offers. The two bulk actions reuse the single-asset rules, so nothing new decides what may be deleted. |
| Crop previews 16:9 / 4:3 / 1:1 / 9:16 | CSS only: four boxes with `aspect-ratio` and `object-fit: cover; object-position: var(--fx) var(--fy)`, fed by the focal picker's values and updated live as the point moves. They are a preview, not files. The image editor's real "formats" stay as they are. | The board shows a fixed set; the config formats are a separate, per-site list. |
| Dashboard "Needs you" | **Folio extension API**: `#[DashboardItem]` on a type customization method `fn(): ?Preflow\Folio\Dashboard\NeedsYou`, where `final readonly class NeedsYou { string $title; ?string $text = null; string $url; string $tone = 'warning'; ?string $icon = null; }` with tone `warning\|info\|danger` (a boot error otherwise). It follows the same call rules as `#[DashboardNotice]`: it runs only for `{type}.view`, a throw shows nothing, and items follow `#[DashboardNotice]`'s order (by type, in the order the types' customizations were registered, then extension name). Built-in items: new permissions (`NewPermissions::count()`, for `rbac_role.edit`); one item per publishing type with changes that are not live (`Publisher::states()`, linking to that list's "Changes not live" filter); not-found addresses to check (`count(NotFoundEntries::visible())` ≥ 1, for `redirects.manage`); machine translations waiting for review (today's review queue count). The section is hidden when there are no items. `#[DashboardNotice]` keeps working and renders above the section. | The board's cards need a title, text and target, which raw HTML cannot give. Notices stay for compatibility. |
| Dashboard counts | `QueryBuilder::aggregate()->count()` per type, and `AssetPage->total` from a `query(perPage: 1)` for assets. | Today the dashboard loads every record just to count it. |
| Dashboard "Content" | Types are grouped by nav section (`AdminNav::sectionOrder()` / `sectionLabel()`), one card per section with rows (type icon, label, count, "+" for `{type}.create` when the type is not a singleton). A site with a single section shows one card with no heading. | This is HolzDashboard's grouping, and the single-section case is Dashboard's. |
| Dashboard "Recent changes" | Not in 0.76. It needs a cross-type activity source, which is the 0.77 proposal. | It is new data, and revisions cover publishing types only. |
| Ink marks | Folio: `Preflow\Folio\View\InkMarks::place(int $seed, int $count, array $area): list<array{mark: string, x: float, y: float, size: float, rotate: int, hue: int}>`. It uses a deterministic PRNG (mulberry32 on `$seed`), `$area = ['x' => [0.5, 1.0], 'y' => [0, 1]]` as fractions, marks drawn from the nine `mark-*` names, and hue `1..6`. Twig function `folio_ink_marks(seed, count, area)` renders `<svg class="folio-ink-marks" aria-hidden="true">` with `<use href="{{ folio_asset('icons.svg') }}#mark-…" class="mc-N">`. The sign-in keeps its 50 hand-placed marks, rewritten to `<use … #mark-*>` with the same transforms. | INK.md says the sign-in works and is the reference, and its placement was tuned once. New places use the generator. |
| Admin "not found" | Folio: `Preflow\Folio\Http\NotFound::response(ServerRequestInterface $request, string $message): ResponseInterface`, mirroring `Forbidden::response()`. A document request (not `HX-Request`, not `Sec-Fetch-Mode: cors`, and `Accept` naming `text/html`) gets the ink 404 page with the message as a muted line. Everything else gets today's plain text. Every `new Response(404, [], FolioText::get(...))` in `packages/folio/src/Http` goes through it (a scan test forbids new ones). The hint "→ add a redirect" shows for `redirects.manage` and links to `{prefix}/redirects/new?address=<path>`. `RedirectsController::create()` accepts `address=`, which is prefilled, validated as today and only a path. | It is one renderer, explicit at each site like `Forbidden`. Tests that assert plain bodies send no HTML `Accept`, and the tests show which do. |
| Roles "implied" ticks | No implications. The permission engine checks exact names (`Access::can()`, `FolioPermissionMiddleware`), so Edit does not grant View. The matrix shows granted and n/a ("–") only. The legend drops "Folgt aus einer anderen Berechtigung" and the footnote keeps only "Spaltenköpfe schalten die ganze Spalte." This is recorded as an Adaptation in the deviations note, and the owner is asked under "Needs the owner". | A dashed tick would promise access the server does not give. |
| Roles "Neu" and "Nur neue (N)" | `PermissionsFieldType` gets `?KnownPermissions` (via its provider wiring) and marks names in `KnownPermissions::fresh()`, but only for a user with `rbac_role.edit`, as `NewPermissions::forManager` does. | It is the same source as the dashboard and list notices. |
| Translations "Changed only" | A GET parameter `changed=1` filters `screen()`'s rows to those with an override, and the count shows in the toggle. | The count exists already (`row['override']`). |
| Redirect form in a drawer | The list opens new and edit forms with `Folio.openDrawer()`. The form renders with `_drawer_layout.twig` when `_drawer=1` and as a full page otherwise (a link without JS). After a save the drawer posts `{source: 'folio-drawer', type: 'redirect'}` and the list reloads. | The drawer mechanics exist (relation "New", asset picker). Without JS it is still a page. |

## Global Constraints

- Handoff rules:
  - no build step, no Tailwind, no JS framework;
  - keep existing class names, and give new ones the `folio-` prefix;
  - keep every translation key, and put new text in `lang/en|de|fr/folio.php` (all three);
  - accessibility as today or better: real buttons and links, `aria-label` on icon buttons, 4.5:1 contrast, the `--focus-ring` focus ring, `prefers-reduced-motion`;
  - template tests where the Twig structure changes.
- Owner rules:
  - the framework holds abstractions only, and Folio is only the UI adapter;
  - no data hard-coded in Folio templates: no type key, hue name or token in a template (`TypeIconTemplateTest` scans for `--c-type-`);
  - no workarounds;
  - mails never mention Folio.
- INK.md rules:
  - ink stays ink in light mode;
  - emerald means action, and the other five hues only mark types;
  - marks are `aria-hidden`;
  - reduced motion stops drift and caret;
  - no marks inside forms, tables or the editor body;
  - at most one ink place per screen.
- Tests that pin today's markup (inventory "Tests pinning" per section) change in the same commit as the markup. Each changed assertion must still assert the behaviour it guarded: a hook, a value or an order, never weaker than it was.
- `AdminCssTest` holds: every `var(--x)` is defined, and if a selector is dropped from the bordered-surface list, the test list changes with it.
- Not in this release (0.77, all approved):
  - the ⌘K palette and search entry;
  - the `/` block picker and the insert line;
  - AI "Write a draft";
  - the recent-changes feed and its activity source;
  - the tag field type.
- Every screen works in light and dark at 1440 and 375 (no horizontal page scroll at 375).
- Packages touched: media, folio and starter-folio (pins). Constraints are raised together.
- Tests:
  - `vendor/bin/phpunit --testsuite Folio` plus `--testsuite Media`;
  - `node --test packages/folio/tests/js/`;
  - `composer test:starters`;
  - one run at a time.
- Visual check per task: a scratch copy of `starter-folio` with demo data, headless Chrome, light and dark, 1440 and 375, beside the named boards. Differences that stay go into the deviations note, one label each.

## Review Focus

1. **The asset bulk actions refuse exactly what the single actions refuse.** A used asset is not binned (it is named in the flash), the rest are binned, CSRF and `assets.delete` are checked once, and an id from another library or a binned asset is skipped. Covered by Task 4 `AssetBulkTest::test_bin_refuses_used_assets_and_bins_the_rest`, `test_bulk_needs_permission_and_csrf`.
2. **"Missing alt text" counts and filters the same set.** That set is images only, alt in the default locale null or empty, live assets only (not binned, not private copies hidden today). The count in the toggle equals the filtered `total`. Covered by Task 4 `MediaLibraryMissingAltTest`.
3. **The admin 404 page reaches only document requests.** htmx, fetch and JSON callers still get the plain text (or JSON) they parse. The `address=` prefill accepts only a site path (no scheme, no `//`). Covered by Task 2 `NotFoundPageTest::test_htmx_and_fetch_keep_plain_text` and `RedirectsControllerTest::test_address_prefill_only_takes_a_path`.
4. **The roles matrix submits exactly the names the boxes show:**
   - row switches and column toggles set the same `permissions[]` as clicking each box;
   - delegation-denied boxes stay disabled and are never toggled by a row or column switch;
   - "Nur neue" only hides rows and never drops their values;
   - "Alles erlauben" still sends `*`.

   Covered by Task 9 `tests/js/rbac-matrix.test.mjs` and `PermissionsFieldTest::test_hidden_rows_still_submit`.
5. **Translations: no change is lost.**
   - "Save all" posts every changed row, including rows hidden by "Changed only" or the search.
   - Discard restores `defaultValue`.
   - An in-admin link while changes are open opens the styled leave dialog (`Folio.unsaved`), and a confirmed leave doesn't also fire the native prompt.

   Covered by Task 6 `tests/js/translations.test.mjs`.
