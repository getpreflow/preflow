# Release 0.48 checklist

AI translation in the background. Spec: `docs/superpowers/specs/2026-10-30-ai-translation-background-design.md`,
plan: `docs/superpowers/plans/2026-10-30-ai-translation-background.md`.

- **preflow/i18n:** a job queue with a state `queued`, a lease per record (so a worker and a browser page never
  translate the same record at once), `TranslationWorker`, the console command `translate:work [--seconds=50]`
  for cron, a job prefix, the go-live confirmation stored on the job, and the review index (`ReviewIndex`,
  `storage/ai/review.json`). See "Background translation" in `packages/i18n/README.md`.
- **preflow/folio:** Translate on a record queues a job instead of filling the form (everything the record holds,
  saved as a draft with "not checked" marks). The run screen is a status page and can still drive steps while it is
  open. The dashboard has a "Waiting for review" section. Publishing clears the "not checked" marks of the
  languages the record is visible in. `folio:review-index` rebuilds the index. Settings → Translations says what to
  do when the source language is selected. Labels and alt texts still fill their inputs.

## Breaking changes and upgrade notes

- **Version 0.48.0**, because a setting is removed. `publishing.checked_translations` is ignored now (no error),
  and the warning after publishing is gone. Publishing is the check.
- **Sites with AI on need a cron line:** `* * * * * cd <app> && php vendor/bin/preflow translate:work`.
  Without it, queued jobs wait; the dialog, the status page and the dashboard say so. The command prints only
  when it worked records or stopped, so cron mails nothing on idle minutes.
- **Run `php vendor/bin/preflow folio:review-index` once** after upgrading, to fill the review index.
- **`Publisher`'s constructor changed.** The 8th parameter, `bool $checkedTranslations`, is replaced by
  `?ReviewIndexUpdater $review`. Code that builds a `Publisher` itself and passes that argument by position must
  drop the bool (or pass a `ReviewIndexUpdater`); named arguments `checkedTranslations:` fail. Folio's own wiring
  needs nothing.
- **Before adding the cron line, look at `storage/ai/jobs`.** Runs that 0.47 left "running" (a closed run page)
  are continued by the worker on its first minute, and paid for. Stop the ones you do not want first (the run
  screen's Stop, or set `"state": "stopped"` in the job's JSON file).
- **No new SQL columns.** `preflow migrate` is not needed for this release.

## 0.48.1 (branch `fix/ai-progress`)

- **fix(folio): AI writes land despite unrelated saves.** `FolioTextSource::write()` saved against the version
  `units()` had seen, so any save during a run (the edit form's autosave, another field, even opening the
  Translate dialog) threw the whole paid translation away as "conflict". It now saves against the version it just
  read. Texts a person changed meanwhile are still left alone (`leftAlone`), other fields are kept, and a save
  landing between `write()`'s own read and save makes it start over once (a second one is a Conflict). A text
  whose English changed meanwhile is written but stamped with the English that was sent
  (`TranslationStatus::madeFrom()`), so it shows as outdated instead of passing for current.
- **feat(i18n): progress.** New `ReportsProgress` (`reportProgressTo(?Closure(int $done, int $total))`);
  `AiTranslator` reports after each request (split halves as they finish). `JobRunner` stores
  `progress => {locale, done, total}` on the item in hand (locked merge, only while the item is pending, never
  touching other items or a stop), before the first request and after each one; it goes away when the item is
  through or the provider is unavailable. A job another driver set back to `queued` shows `running` again.
- **feat(folio): progress on screen.** Dashboard job rows and the run screen show the record being translated
  with a `<progress>` bar and "120 of 410 texts"; the edit form's pending line says how far it is. While a job is
  queued or running, the dashboard's review section refreshes itself every 5 s (`GET {prefix}?review=1` with
  htmx, the section alone) and stops when none is. Strings in en, de, fr. The run screen's cost no longer shows
  "&lt;" escaped twice.
- **Tests, 2026-10-31:** `vendor/bin/phpunit` (whole monorepo) 4913 tests OK (176 skipped, 99 PHPUnit
  deprecations from `core` and `roles` tests, unrelated); `composer test:mysql` 177 tests OK;
  `node --test 'packages/folio/tests/js/*.test.mjs'` 5 of 5 pass.
- **feat(i18n): protected tokens.** `config/ai.php` `translation.protected_tokens` lists regexes for a project's
  own tokens. A machine translation must keep their matches; with a capture group 1, only that part has to stay,
  so `{{glossary:key|shown text}}` may translate the shown text. Otherwise the unit fails as "markup changed".
  The patterns also go into the prompt, and an invalid pattern throws, naming the key.
- **Review fixes:**
  - A failed progress write is logged and never fails the item.
  - An invalid protected-token pattern names the PCRE compile error.
  - Whether a pattern has a group 1 is decided once per pattern, and a pattern that cannot run fails the check.
  - Jobs carry `updated_at`, stamped on every save, and the dashboard stops polling for jobs unchanged for 10 minutes.
  Tests after this change, 2026-10-31: whole monorepo 4924 OK (176 skipped); `composer test:mysql` 177 OK; JS 5/5.
- No new SQL columns and no new routes. The only new config is the optional `translation.protected_tokens`.
  Upgrading: `composer update 'preflow/*'`.
