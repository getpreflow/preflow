# Release 0.75 — Folio redesign, part 2: lists and editors Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Folio's lists and editors take the redesign (handoff phases 4–5), with the self-hosted fonts, and the data those screens need comes from public APIs in the packages that own it.

**Architecture:** Same as 0.73: server-rendered Twig, one `light-dark()` token set in `admin.css`, framework-free `admin.js`, no build step. New here: three small public APIs in package cores (a type/block *family* vocabulary in `data`, a locale *completeness* vocabulary in `i18n`, `Publisher::changes()` in `publishing`) and a relation `metaField` in `data`; Folio only reads them and maps them to classes and tokens. The editor's Save/Publish move into the topbar and reach the record form through the HTML `form` attribute; the side panel sits outside the `<form>` (extension panels carry forms of their own), and its record controls use the same attribute. Settings and library screens and the ink layer follow in 0.76.

**Tech Stack:** Twig, CSS, vanilla JS (`node --test packages/folio/tests/js/`), PHP 8.4 / PHPUnit 11, htmx 2.0.11 (vendored in `preflow/htmx`).

**Spec:** the owner's handoff at `.superpowers/folio-redesign/folio-redesign-handoff/` (git-ignored): `README.md` (rules), `PLAN.md` phases 4–5, `SCREENS.md` (Lists, Entry editor, Page editor with blocks, Reference editor), `COMPONENTS.md` (§1 split button, segmented with locale dots, tabs, save state, language indicator, type icons; §2 form fields; §3 toolbar, filter menu, table, bulk bar, pager, revisions, review queue; §4 menus, block card, blocks picker, preview, share link), `icons.md`, boards `List`, `PagesList`, `PageEditor`, `RecordEditor`, `ReferenceEdit`, `LibFields`, `LibData`, `LibOverlays`. Every row labelled **0.75** in `docs/superpowers/notes/2026-11-13-folio-redesign-deviations.md` is covered below; the inventory (`docs/superpowers/notes/2026-11-13-folio-redesign-inventory.md` §8 items 1, 3, 4, 6–10) names the fitting problems this plan rules on. Owner, 2026-11-13: fonts approved (files in `packages/folio/assets/fonts/`, untracked).

## Data rulings

| Question | Ruling | Why |
|---|---|---|
| Where type and block hues are declared | A shared vocabulary `enum Preflow\Data\TypeFamily: string { Page = 'page'; Reference = 'reference'; Asset = 'asset'; Member = 'member'; Shop = 'shop'; Live = 'live'; }` in **data**. A type declares `"family": "<value>"` in its schema (model JSON, or the admin JSON file of a model class, beside the existing `"icon"`, `"section"`, `"order"`); a block declares `#[Block(..., family: TypeFamily::Asset)]` (new last parameter `?TypeFamily $family = null`) in **blocks** (`BlockDefinition::$family`). Folio's `TypeCatalog` validates the schema value with `TypeFamily::tryFrom()` (boot error otherwise) and exposes `TypeListing::$family` (`?TypeFamily`). | One vocabulary both packages share without depending on Folio; a site building its own admin reads it from `TypeRegistry::schema()` / `BlockRegistry`. The schema already carries the admin keys `icon`/`section`, so classes and files declare it the same way. |
| Default when a site declares nothing | Types: a type with a `"frontend"` block → `page`; a user type (`"users"`) → `member`; anything else → no family. Blocks: no family. Folio's own Assets nav/library → `asset` (Folio's own declaration, `AdminNav::add(..., family: TypeFamily::Asset)`). No family = neutral tile (`--c-neutral-soft` background, `--c-text-muted` glyph). | A tint has to mean something the site said; only these two shapes say it unambiguously. A neutral tile is honest, never wrong. |
| Glyph in the tile | The type's own `icon` (today's default `ui-file` / `ui-settings`), the block's own `icon` (default `block`). Family marks (`mark-*`) are not used as glyphs in 0.75. | Every type and block already has an icon; the marks move into `icons.svg` with the ink layer (0.76). |
| How the 10 `--c-type-*` tokens map | `page` → `--c-type-page`/`-soft` (sky), `reference` → `--c-type-reference`/`-soft` (violet), `asset` → `--c-type-asset`/`-soft` (amber), `member` → `--c-type-member`/`-soft` (lime), `shop` → `--c-type-shop`/`-soft` (rose), `live` → `--c-accent-text`/`--c-accent-soft` (the sixth sign-in hue, emerald; the HolzDashboard board tints CO₂-Rechner this way). Only CSS maps them: `.folio-type-icon[data-family="page"] { background: var(--c-type-page-soft); color: var(--c-type-page); }` etc. | Five token pairs plus the accent are the six hues of the sign-in marks (tokens.css comment). No template ever names a token. |
| The "partial" locale state | `enum Preflow\I18n\Completeness: string { Complete = 'complete'; Partial = 'partial'; Missing = 'missing'; public static function of(bool $visible, int $total, int $missing): self }` in **i18n**: not visible in the locale → `Missing`; `$total === 0` or `$missing === 0` → `Complete`; `$missing >= $total` → `Missing`; else `Partial`. Folio computes it: `TranslationStatus::state(TypeDefinition, DynamicRecord, string $locale): LocaleState` (new `final readonly class Preflow\Folio\Content\LocaleState { Completeness $completeness; int $total; int $missing; int $outdated; int $unchecked; }`), where `$total` = texts the default locale has (`texts()`, which already includes block leaves via `ReportsTranslatableTexts`) and `$missing` = `missing()`. It reads `texts()` once per call (today's list calls it three times per locale). | The record already knows its translatable texts per locale (`TranslationStatus::texts()/missing()`), so no new storage. The vocabulary is generic (i18n); the counting stays where the field types report their texts. |
| Outdated / not-checked texts | Stay visible: the indicator item of a locale with `outdated + unchecked > 0` gets `is-stale` (a 4px warning dot after the code) and its `title` lists the existing `folio.list.outdated` / `folio.list.unchecked` texts; unchecked keeps its link to `?unchecked=1`. | The three-state indicator must not hide what today's badges say (accessibility and information as today or better). |
| Topbar Save/Publish | The record form gets `id="folio-record"`. Save draft, the Publish split button and the publish-at input render in `{% block actions %}` with `form="folio-record"`; side-panel record controls (visible-in checkboxes, address fields, `"panel": "side"` fields) carry `form="folio-record"` too. Busy state is unchanged (it keys off `e.submitter`, which is the outside button). The unsaved guard listens on `document` and marks `e.target.form` (so outside controls count); autosave's `hx-trigger` gains `input from:[form=folio-record] delay:3s, change from:[form=folio-record] delay:3s`; `hx-disabled-elt` becomes `button[type=submit][form=folio-record], find button[type=submit]`. The hidden default submit stays inside the form (Enter saves). | Native HTML, works without JS; no second form, no JS copying of values. |
| "N changes · compare" | `Publisher::changes(DynamicRecord $working): list<string>` in **publishing** (field names whose working value differs from the live snapshot; empty for a draft never published; same comparison as the private `changedFields()`, which it reuses). The side panel shows "N changes" as a `<details>` listing the field labels. No diff view. | Data in the core; a side-by-side compare screen is a new feature (see below). |
| Relation meta line | `Relation::$metaField` (`?string`, JSON `"metaField"`, attribute `#[Relation(metaField: 'email')]`) in **data**, beside `labelField`; `RelationLabels` returns `{label, meta}`. Avatar = initials of the label on the target type's family tile. | Same shape as `labelField`, which already lives in data. |

## Global Constraints

- Handoff rules: no build step, no Tailwind, no JS framework; keep class names, new ones `folio-`; keep every translation key, new text in `lang/en|de|fr/folio.php` (all three; package lang files likewise); accessibility as today or better (real buttons/links, `aria-label` on icon buttons, 4.5:1, focus ring `--focus-ring`, `prefers-reduced-motion`); template tests where Twig structure changes.
- Owner rules: framework = abstractions; Folio only the UI adapter; no data hard-coded in Folio templates (no type key, hue name or token in a template; a test scans for `--c-type-`); no workarounds; mails never mention Folio.
- Fonts (replaces the 0.73 constraint): Inter (variable, upright, 100–900) and JetBrains Mono (Regular, Medium) ship self-hosted under `assets/fonts/` with their OFL files (Task 1). Italics are synthesized.
- Not in this release: settings and library screens, ink layer, dashboard (0.76); proposals that need the owner's yes: ⌘K palette, styled confirm, `/` block picker and insert line, crop previews, missing-alt filter, AI "Write a draft", recent-changes feed, and the new items under "Needs the owner".
- Every screen works in light and dark at 1440 and 375 (no horizontal page scroll at 375).
- Packages touched: data, blocks, i18n, publishing, folio, starter-folio (model files declare families). Constraints are raised together.
- Tests: `vendor/bin/phpunit --testsuite Folio` plus the touched packages' suites, `node --test packages/folio/tests/js/`, `composer test:starters`; one run at a time.
- Visual check per task: a scratch copy of `starter-folio` with demo data, headless Chrome, light and dark, 1440 and 375, beside the named boards; differences that stay go into the deviations note (one label each).

**Files:** `packages/folio/assets/fonts/*` (add to git as they are), `assets/admin.css` (top, before `:root`), `src/FolioServiceProvider.php` (`assetMap()`), `src/Http/AssetController.php` (`contentType()`, charset), `templates/admin/_layout.twig`, `_auth_layout.twig`, `_drawer_layout.twig` (preload), `tests/Http/FontsTest.php` (new), deviations note (font row → "Fixed in 0.75").

Check: `git ls-files packages/folio/assets/fonts` lists all five; no `.gitattributes`/`archive` rule excludes them (none today); `composer test:starters` installs them.
- Tests (`FontsTest`): each woff2 → 200, `Content-Type: font/woff2` (no charset), immutable cache; every `url()` in admin.css's `@font-face` names a served file and its `v` equals `substr(hash_file('xxh3', …), 0, 12)` (Review Focus 5); `@font-face` families equal the first names in `--font-sans`/`--font-mono`; both OFL files exist next to the fonts; the sign-in page HTML links admin.css and the preload.
