# Release 0.46.1 checklist

A bug fix release for `folio:import` and `folio:pull`. Branch: `fix/folio-import-order`.

## The bug

`php preflow folio:pull production` on BG Genius stopped part-way with
`SQLSTATE[23000]: UNIQUE constraint failed: game.slug`. Local and live had the same games with the same slugs, but
under different ids, because each side had created them separately. The importer wrote the incoming records before
it removed the local ones the export does not have, so the live game's slug hit the local game that still held it.
Records were written one by one without a transaction, so the earlier tables and rows were already changed and the
local content was mixed until the backup was imported again.

It hits every SQL table with a unique field (SQLite and MySQL) when a unique value moves from one id to another, or
when two records swap values. `__published` tables have only a plain index on unique fields, the asset table and the
override table have none. JSON storage has no unique index, so there it only lacked the all-or-nothing part.

## The fix (preflow/folio)

- `Importer::apply()` writes the records of all tables in one go before any file: for each table it deletes the
  removed rows and the rows it replaces first, then writes the incoming ones. A slug that has another id live, or
  two records swapping slugs, no longer collides.
- SQL storages run it in one transaction per connection (begun only when none is open). Other storages (JSON) keep
  the rows the import replaces or removes and write them back on failure.
- On a failure there, nothing changes and `apply()` throws a `TransferException` with code
  `Importer::RECORDS_UNCHANGED`. `folio:import` and `folio:pull` then say `Import failed, nothing was changed`
  instead of "stopped part-way". A failure while writing files (after the records) is reported as before, with the
  backup to restore.
- A replaced SQL row is now deleted and inserted, not updated in place: a local column the export does not carry
  (a field only the local models have) is empty after the import, as it already was for JSON storage.
- Media, uploads, private media and version files are unchanged (no unique values, no ordering bug).
- Folio README, `folio:pull`: one bullet "Records all or nothing".
