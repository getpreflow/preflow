# Folio and Media Gaps from BG Genius Phase 3 (0.46) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the seven generic gaps BG Genius Phase 3 (its admin moved onto Folio, English and German) ran into, so
it can drop its workarounds and go live on 0.46: decimal number fields, German share links, component actions that
keep the page's locale, composite indexes in migrations, unlimited revisions, a configurable Folio cache directory,
and HEIC/HEIF photos in the media library.

**Architecture:** Each gap is fixed in the package core that owns it, behind a public interface. Folio stays the UI
adapter. `preflow/validation` gets a `step` rule that Folio's number field uses. `FrontendResolver` gets an unprefixed
`pathFor()`, which the shared preview compares. `LocaleMiddleware` remembers the URL prefix it stripped. Core hands
that prefix to the `hd` helpers, so component URLs start with `/de/--component/…` and pass through the same
middleware again. `Table` gets `unique()` and `index()` over several columns. `Publisher` takes `0` or `null` as
"keep all". Folio reads `cache_path`. `MediaLibrary` converts HEIC/HEIF to a JPEG through an injectable
`HeicConverter`, or refuses with a message Folio translates.

**Tech Stack:** PHP 8.4+, Preflow monorepo (`packages/validation`, `folio`, `i18n`, `htmx`, `core`, `data`, `media`),
PHPUnit 11, Twig, Imagick (libheif) for HEIC.

**Spec:** The owner's brief of 2026-10-29 ("BG Genius Phase 3 gaps, release 0.46"). Background:
`/Users/smyr/Sites/gbits/bggenius-preflow/docs/superpowers/specs/2026-10-29-phase3-into-folio-design.md`. This plan
ships as v0.46.0. The release checklist is `docs/superpowers/plans/2026-10-29-release-0.46-checklist.md`.

**What recon changed in the brief (read before starting):**

- **Gap 1:** the server already accepts decimals. `NumberFieldType::rules()` returns `[]`, so nothing checks a number
  field unless the model lists `validate` rules. Only the browser refuses 2.5, because an input without `step`
  defaults to step 1. The fix is the `step` attribute plus a new `step` rule. No current rule refuses decimals. A
  model with `"validate": ["integer"]` still refuses them, as intended.
- **Gap 3:** the endpoint path is built by `HtmxExtensionProvider` (`packages/htmx/src/HtmxExtensionProvider.php`,
  wired in `Application::bootComponentLayer()`), not by preflow/components. `Kernel` checks the *stripped* path for
  `/--component`, and `LocaleMiddleware` runs before session, CSRF and the kernel. So `/de/--component/action` already
  reaches the endpoint with locale `de` and the CSRF exemption. The only gap is that nothing puts `/de` into the URL.
  `packages/twig/src/HdExtension.php` is an older twin that `Application` does not wire. It stays unchanged.
- **Gap 7:** `MASTER_EXTENSIONS` does not convert AVIF on import. AVIF originals are stored as AVIF, and only an
  *edited* AVIF's rendered master becomes WebP. HEIC needs a new step at intake, because browsers other than Safari
  cannot show it. `ImageTag.php:128` is the branch for legacy paths (pre-library `Y/m/{id}.ext` values). A converted
  HEIC is stored as a `.jpg` asset, so that branch, `EDITABLE` and `VariantGenerator::SOURCE_TYPES` need no change.
  The library's messages are English in the core and are translated by Folio's `MediaMessages` patterns. That is the
  translatable path for the refusal.
- **Gap 6:** core also writes `storage/cache/data`, `storage/cache/blade` and the Twig cache under the project.
  That is out of scope. The brief and the BG Genius test guard concern `folio-*.cache` and the overrides.

## Global Constraints

- Generic only: no BG Genius concept in any package. Features live in the package cores with public interfaces;
  Folio is the UI adapter (owner's rule, 2026-10-26).
- Opt-in or harmless for existing sites. With no new config, behaviour is unchanged, except that HEIC uploads now
  work (or are refused with a clear reason) instead of "type not allowed", and that `revisions: 0` now means "keep
  all" (it used to keep 1; this was undocumented).
- Every change is documented in its package README; `ROADMAP.md` gets an entry.
- `lang/en`, `lang/de` and `lang/fr` keep identical keys: Folio's `tests/TranslationsDeclarationTest.php`, and the
  same for `packages/validation/lang/*`.
- A package that calls an API new in 0.46 conflicts with the older release, and its `ComposerConstraintsTest`
  pins the new conflict:
  - folio → validation `<0.46`
  - core → htmx `<0.46` and i18n `<0.46`
- No new column, so no `preflow migrate` step for 0.46.
- After the release: smeyer.me, smart-stack.works and holz-objekte.org are upgraded and deployed (standing rule).

## Review Focus

1. **A step that floats cannot represent exactly** (`0.1`, value `0.3`; `0.01`, value `19.99`) must be accepted, not

2. **A component on a German page that a component action re-renders** must keep `/de/--component/…` in its new

3. **A HEIC phone photo in portrait** must come out upright and with swapped width/height exactly once: neither

### Task 3: Component actions keep the page's locale prefix

**Decision — prefix the endpoint URL, do not sign the locale into the token.** A component URL made on a `/de/…` page
becomes `/de/--component/action?token=…`. `LocaleMiddleware` already strips `/de`, sets the translator and the
`locale` request attribute, and then hands `/--component/…` to session, CSRF (exempt) and the kernel. No component,
endpoint or token code changes.

A locale in the token would make preflow/htmx (which knows nothing about i18n) redo the middleware's job: set the
translator, rewrite the request attribute, and stay in step with the cookie strategy. It would also change the token
format. With the prefix, `url_strategy: none` is untouched: there is no prefix, and the cookie carries the locale, as
today. Pages without a prefix and Folio's admin (`/folio`) get exactly today's URLs.

**Files:**
- Modify: `packages/i18n/src/LocaleMiddleware.php` (remember the stripped prefix), `packages/i18n/README.md`,
  `packages/htmx/src/HtmxExtensionProvider.php` (optional path-prefix closure for `actionUrl`, `post`, `get`, `on`),
  `packages/htmx/README.md`, `packages/core/src/Application.php:829` (pass the closure) and `:929` (register the
  middleware instance), `packages/core/composer.json` (conflicts), `packages/core/tests/ComposerConstraintsTest.php`
- Create: `packages/core/tests/ComponentLocalePrefixTest.php`
- Test: `packages/i18n/tests/LocaleMiddlewareTest.php`, `packages/htmx/tests/HtmxExtensionProviderTest.php`

**Interfaces:**
- Produces: `LocaleMiddleware::urlPrefix(): string`. During a request whose URL carried a locale prefix it returns
  that prefix (`'/de'`; `'/en'` when the default was in the URL), and `''` otherwise. It is reset at the start of
  every `process()` call. Core registers the instance as `Preflow\I18n\LocaleMiddleware::class` in the container.
- Produces: `HtmxExtensionProvider::__construct(HypermediaDriver $driver, ComponentToken $token, string $endpointPrefix
  = '/--component', ?HtmxAssets $assets = null, ?\Closure $pathPrefix = null)`. `$pathPrefix` is a
  `\Closure(): string`. Every URL the provider builds is `($pathPrefix)() . $endpointPrefix . '/…'`.
- Consumes (core): `fn (): string => $container->has(LocaleMiddleware::class) ? $container->get(LocaleMiddleware::class)->urlPrefix() : ''`.
  It is lazy, because `bootComponentLayer()` runs before `bootI18n()`.

### Task 7: HEIC/HEIF photos in the media library

**Decision — the HEIC original is not kept.** The JPEG becomes the asset's original file. The reasons:
- Only Safari displays HEIC.
- Every library feature (variants, editing, boxes, colours, versions, the bin, private files, cleanup) works on the
  asset's single file. A second file would need its own lifecycle in all of them.
- A quality-92 JPEG with the ICC profile and EXIF kept loses nothing an editor or a page can see.
- The original name becomes `IMG_1234.jpg`, so downloads match the content.

A site that must archive camera originals keeps them outside the library.

**Interfaces:**
- Produces: `interface Preflow\Media\Image\HeicConverter { public function available(): bool; public function toJpeg(string $bytes): string; }`.
  `toJpeg()` throws `\RuntimeException` when the file cannot be decoded.
- Produces: `final class ImagickHeicConverter implements HeicConverter`.
  - `available()`: `class_exists(\Imagick::class)` and `\Imagick::queryFormats('HEIC') !== []`. HEIF files are
    read through the same libheif delegate.
  - `toJpeg()`: `readImageBlob`, `setImageOrientation(\Imagick::ORIENTATION_TOPLEFT)`, format `jpeg`, quality 92;
    profiles (ICC, EXIF) are not stripped.
  - Orientation: libheif already applies `irot`/`imir` when it decodes, so the pixels come out upright and the
    JPEG must say orientation 1. That keeps `Orientation::of()` and `dimensions()` consistent with other JPEGs, and
    the ICC profile lets `ColorManagement` convert P3 phone photos to sRGB variants as it does for JPEGs.
- Produces: `MediaLibrary` intake. A sniffed `image/heic` or `image/heif`:
  - **Converter available:** replaced by the converted bytes, MIME `image/jpeg`, extension `jpg` and the name's
    extension `.jpg`. `max_bytes` stays a check on the uploaded file.
  - **Converter not available:** `AssetUploadException("{$name}: HEIC/HEIF images need Imagick with HEIC support on the server, which is missing.")`.
  - **Decode fails:** `AssetUploadException("{$name}: the HEIC/HEIF image could not be converted.")`.
  - In both refusals nothing is written.
  - `image/heic-sequence` and `image/heif-sequence` stay "type not allowed".
