# 0.63.2 Patch Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** fix the framework bugs, security gaps and README mismatches found while writing the preflow.dev Build guides, and release them as 0.63.2.

**Architecture:** monorepo `/Users/smyr/Sites/gbits/preflow-framework` (branch main), one task per package group. Each fix gets a failing test first in the package's own `tests/`. Items too large for a patch go into ROADMAP.md (Task 6), not into code.

**Tech Stack:** PHP 8.4+, PHPUnit (root `phpunit.xml`, per-package suites: `vendor/bin/phpunit --testsuite <Package>` or a path), SQLite and MySQL (`composer test:mysql`), starters (`composer test:starters`).

**Spec:** none. The source is the follow-up list collected on 2026-11-10 (copied into Task 6 below as "Deferred" and into the tasks as "Fix"); the owner's standing rules apply: features live in packages behind public interfaces, patch releases keep public APIs compatible, and every site upgrades after a release. Rulings made without a spec are provisional.

## Global Constraints

- **Compatible:** no public method removed or renamed; a method may gain an optional parameter. Behaviour changes only where the old behaviour was a bug (each listed under "Upgrading" in the ROADMAP 0.63.2 entry).
- **Security fixes refuse, they don't repair:** an invalid operator or identifier throws `\InvalidArgumentException` naming the bad value (escaped for display), before any SQL is built.
- READMEs change only where they are wrong; keep them short (docs phase 4 shrinks them).
- Never run two test suites at once. Commit locally only (the controller tags, pushes and deploys).
- No new dependencies.

## Review Focus

1. A query that uses an operator the whitelist forgets (`NOT IN`, `NOT LIKE`, `<>`, lower-case `like`, `in`) and that Folio, members, media or the starters use today — the whitelist must not break existing callers (grep every `->where(`/`whereAny(` in `packages/*/src` and the starters).
2. A field name that is legitimate today but fails the new identifier rule (dotted JSON paths like `data.title`, hyphens in Folio field keys) — the rule must match what the drivers actually accept, or the JSON-path form must go through its own validated path.
3. An `HttpException` thrown inside a nested component: the whole page answers with that status (not the boundary fallback with 200), and in production the error page shows no exception text.
4. A page-cached `.md` GEO view: after caching, the `{% apply geo %}` blocks are still present.
5. A folder starting with `_` anywhere in `app/pages` (also nested, e.g. `app/pages/blog/_partials/x.twig`) is never a route.

### Task 1: data — query safety and model correctness

**Files:** `packages/data/src/Query.php`, `QueryBuilder.php`, `Driver/{Dialect,SqliteDialect,MysqlDialect}.php`, the SQL/JSON storage drivers that build WHERE clauses, `DataManager.php`, `ModelMetadata.php`, tests under `packages/data/tests/`, `packages/data/README.md`.

Fix:
- **(SECURITY) operator whitelist:** `where()`, `orWhere()`, `whereAny()` accept only `=`, `!=`, `<>`, `<`, `>`, `<=`, `>=`, `LIKE`, `NOT LIKE`, `IN`, `NOT IN` (case-insensitive, stored upper-case) and the two-argument form (`where(field, value)` = `=`). Anything else throws. Check every operator used in `packages/*/src` and both starters first and add any real one that's missing to the list (and the test).
- **(SECURITY) identifiers:** `quoteIdentifier()` escapes the quote character (SQLite `"` → `""`, MySQL `` ` `` → ``` `` ```) and the query layer validates field names used in `where`/`orderBy` against `^[A-Za-z_][A-Za-z0-9_]*$` (plus whatever separator the JSON-path form uses today — find it, keep it working, validate each segment).
- `where(field, null)` / `where(field, '=', null)` → `IS NULL`; `!=`/`<>` with null → `IS NOT NULL` (SQL drivers and the JSON driver agree).
- A plain `Model` with a string id property that is empty on insert gets a UUID v4 (as Folio types do); `DataManager::insert()` on such a model no longer writes NULL then fails with a TypeError.
- `#[Timestamps]`: read what the attribute documents (docblock/README); make `save()` set the created/updated properties it names. If the attribute's intended property names aren't defined anywhere, rule: `createdAt`/`updatedAt` as `\DateTimeImmutable`, ledger it.
- `#[Field(unique: true)]` on a plain model: find where plain-model tables are created (if anywhere). If the framework creates them, add the unique index; if tables are only ever created by the app's migrations, document in the README that the index belongs in the migration and that the unique rule alone isn't a guard. Report which it was.

- [ ] Failing tests for each item (SQLite and the JSON driver in the normal suite; MySQL covered by `composer test:mysql`): an injected operator (`= 1 OR 1=1 --`) throws; a field name `title" OR 1=1 --` throws; `where('x', null)` finds the null row; insert of a string-id model returns a model with a UUID; timestamps set on create and update.
- [ ] Implement; data suite green; `composer test:mysql` green; then the Folio and members suites (they query a lot).
- [ ] Commit: `fix(data): operator whitelist, safe identifiers, null where, string ids, timestamps`

### Task 3: routing and core — routes, 404, env, request path

**Files:** `packages/routing/src/FileRouteScanner.php`, `packages/core/src/Error/*` (production 404), `packages/core/src/…/EnvLoader.php`, the place that builds `RequestContext`/`request.path` for controller pages, `pages:work` rebuilds and `seo:audit` renders (core PageCache `Rebuild`, view `Audit/PageRenderer`), tests.

Fix:
- `FileRouteScanner` skips every directory whose name starts with `_` (at any depth) and files starting with `_`. `/_views/job` answers 404.
- Production (debug off) 404/405 pages never show the exception message (`No route matches [GET /x]`); they show the app's error template or a plain generic text. Debug keeps the message.
- `EnvLoader`: `A="x y"` → `x y`; `A='x'` → `x`; `A=x # note` → `x`; `A="x # not a comment"` → `x # not a comment`; escaped quotes inside double quotes (`\"`) work. Existing unquoted values unchanged.
- `request.path` is the path without the locale prefix on controller pages in debug, in `pages:work` rebuilds and in `seo:audit` renders (same as normal requests). Find where each sets `RequestContext` from the unstripped request and set it after the locale middleware's stripping (one shared helper if the three share the shape).

- [ ] Failing tests for each (route scanner fixture with `_partials` nested; prod 404 body has no "No route matches"; EnvLoader table test; a rebuild of `/de/jobs` renders `request.path` as `/jobs`).
- [ ] Implement; routing + core + view + i18n suites green.
- [ ] Commit: `fix(routing,core): skip _ folders, quiet production 404, env quotes, request.path without locale`

### Task 4: view, components, blade, geo — rendering

**Files:** `packages/view/src/Geo/GeoMiddleware.php`, `packages/core/src/Http/InternalRender.php` (use, don't change), `packages/blade/src/BladeEngine.php`, `packages/view/src/…` (inline js on full pages), `packages/components/src/ComponentRenderer.php`, components CSS scoping (where `@keyframes`/`@font-face` are handled), tests.

Fix:
- GEO: the `.md` sub-request is marked with `InternalRender::mark()` so the page cache doesn't serve stored HTML to it; the `.md` view of a cached page still contains its `{% apply geo %}` blocks.
- Blade file pages (`app/pages/*.blade.php`) render: `BladeEngine::render()` gets a template it can resolve (view name or path, whichever the file-page renderer passes — make the engine accept what core passes, the Twig engine is the model).
- `{% apply js('inline') %}` output is printed on full pages (where the other page JS is printed), not only in component action responses.
- `ComponentRenderer`: an `HttpException` thrown while rendering (resolveState, template, actions) is rethrown, not turned into the boundary fallback; other throwables keep the boundary behaviour. Ruling (no spec): a 403/404 a component throws means the page itself is forbidden/missing — showing the fallback with 200 hides an access decision. Cost if wrong: a site that relied on the fallback for a component's 404 now gets a 404 page; listed under "Upgrading".
- Components CSS: an unscoped child component no longer inherits the parent's scope; `@keyframes` and `@font-face` inside component CSS are kept (not nested under the scope selector, not dropped); keyframe names stay global (document it).
