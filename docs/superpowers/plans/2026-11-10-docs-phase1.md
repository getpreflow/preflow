# Docs Phase 1 (Foundation) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** the new preflow.dev docs foundation: six-part structure and guide page layout, a generated reference with a completeness check, and the Understand and Start parts written.

**Architecture:** all in the website repo `/Users/smyr/Sites/gbits/preflow-website` (main). Docs stay Markdown under `docs/`, rendered by `DocsController` → `DocsPage`. A `docs:reference` console command installs the released packages into a temp dir, reads their public API statically and writes Markdown + an index under `docs/reference/`. A hand-curated topics map ties reference entries to guides; `docs:check` and a test enforce completeness.

**Tech Stack:** PHP 8.4+, Preflow 0.63.1, league/commonmark (already used), tempest/highlight, nikic/php-parser (dev dependency, generator only), Twig.

**Spec:** `/Users/smyr/Sites/gbits/preflow-framework/docs/superpowers/specs/2026-11-10-docs-design.md` (read "Goals", "Phases", "Anti-goals", "Constraints" and "Decisions for the builder" — they bind every task).

## Global Constraints

- Docs are Markdown in `docs/`; generated files are committed; nothing is generated at request time beyond rendering.
- Every statement true for Preflow 0.63.1; examples are real code from the starters (through the `starter` fence, never pasted) or the packages.
- Voice: plain, friendly, short sentences, concrete; explain any term on first use (glossary links). English only.
- Strict CSP (scripts only via `{% apply js %}`/nonce'd; no inline style attributes); public pages cookie-free and page-cacheable; look carries over (tokens, both themes); responsive to 375 px.
- New URLs: `/docs/understand/*`, `/docs/start/*`, `/docs/build/*`, `/docs/folio/*`, `/docs/extend/*`, `/docs/reference/*`. Old pages stay reachable under an "Older pages" sidebar group until replaced; a replaced page gets a 301 (seeded Folio redirect, as `ContentSeeder::redirects()` does today).
- The DocsController path gate (realpath containment in `docs/`) stays the only way a docs file is read.
- Never run two test suites at once; commit locally only (controller pushes/deploys).

## Review Focus

1. A Markdown file with raw HTML or a `<script>` must not inject script (CommonMark settings; the CSP is the second line).
2. A `starter` fence naming a file that isn't synced shows the StarterCode fallback, page 200.
3. The reference generator against a package with an `@internal` class/method, a trait, an enum, a readonly class, promoted constructor properties and attributes: hidden or documented correctly, no crash.
4. `docs:check` with an orphan entry (public, in no topic) fails with a message naming it; with a pending topic it lists, not fails.
5. The sidebar with ~60 entries stays usable at 375 px (collapsible parts, current part open).

### Task 1: Structure, layout and Markdown extensions

**Files:** `docs/manifest.php` (new format), `app/Components/DocsSidebar`, `app/Components/DocsPage` (+ layout template `app/pages/_views/docs.twig`), `app/Components/TableOfContents`, `app/Markdown/*` (new extensions), `app/Components/DocsSearch` (index the new folders), tests.

- Manifest format: ordered parts `understand, start, build, folio, extend, reference, older`, each `{title, pages: [path => title?]}`; the sidebar renders parts collapsible, the current part open, the current page marked. Titles come from front matter when not given.
- Page footer "Next" / "Previous" from the manifest order; front matter may add `related:` links (shown under "Go deeper").
- Markdown extensions:
  - ```` ```starter <starter> <path> [lines] ```` fence → `StarterCode` (escaped, highlighted, with the GitHub link).
  - ```` ```figure capture:<id> "Caption" ```` → the capture picture or recording (reuse `Captures` + `Recording`).
  - ```` ```diagram <name> ```` → an inline SVG partial from `app/Docs/Diagrams/<name>.svg.twig` (whitelisted names; unknown → nothing, listed by tests).
  - Callouts: `> **Note:**` / `> **Good to know:**` styled blocks.
  - Raw HTML in Markdown is not rendered (CommonMark `html_input: escape` or strip) — the extensions above are the only way to embed rich content.
- Create the empty folders with a placeholder `index.md` per part so the routes exist; move current pages into "Older pages" in the manifest (files stay where they are).
- [ ] Tests: sidebar shows the six parts + "Older pages" in order, current part open; next/previous links follow the manifest; each fence renders (starter code escaped + fallback for an unsynced file; capture figure; diagram; unknown diagram → nothing); raw `<script>` in Markdown is not rendered as a tag; docs search finds a word from a new-folder page; every manifest path renders 200.
- [ ] Implement; visual check (headless Chrome via chrome-php) at 1440/375 both themes; `composer test`.

### Task 2: The reference generator

**Files:** `app/Docs/Reference/*` (generator classes), `app/Console/DocsReferenceCommand.php` (`docs:reference`), `config/docs.php` (package list source = `resources/packages.json`, version = site's Preflow minor), `docs/reference/packages/<package>.md`, `docs/reference/index.json` (every entry: kind, package, id, signature, summary, page anchor), tests with a fixture package under `tests/Fixtures/ReferencePackage/`.

- Install the released packages into a temp dir with Composer (`composer create-project`-free: a temp `composer.json` requiring each `preflow/<name>` at the version), like `starters:sync`; fail without touching `docs/reference/` on any error.
- Read statically with nikic/php-parser (dev dependency): classes, interfaces, traits, enums; public methods and constants; signatures with types/defaults; docblock summary and description; attributes on classes (e.g. `#[Block]`, `#[FolioExtension]`) shown. Hidden: `@internal` classes/methods, non-public members, anything under a `tests/` path.
- Kinds besides classes: template functions (from `new TemplateFunctionDefinition(name: …)` registrations: name, the callable's parameters if resolvable, the preceding comment as description), console commands (command classes: name, description, arguments/options), config keys (from `packages/starter-folio/config/*.php`, `packages/starter/config/*.php` in the installed starters, and package-shipped config files such as `ai/config/ai.php`: file, key path, default, the comment above as description), Folio field types (classes implementing the field type interface: key, label, config options).
- Output per package: title, the README's first paragraph as intro, then sections Classes & interfaces (grouped by namespace), Template functions, Console commands, Config, each entry with an anchor id `<kind>-<name>`. Plus `index.json`.
- [ ] Tests on the fixture package covering Review Focus 3; a test that `index.json` and the pages agree; a test that a failed install leaves `docs/reference/` unchanged.
- [ ] Run `php preflow docs:reference` for real (22 packages); commit the generated files.
- [ ] Commit: `feat(docs): generated reference`

### Task 3: Topics, by-task pages and the completeness check

**Files:** `docs/reference/topics.php`, generated `docs/reference/topics/<topic>.md` (from `docs:reference`), `app/Docs/Reference/Completeness.php`, `app/Console/DocsCheckCommand.php` (`docs:check`), `tests/Integration/DocsCompletenessTest.php`, manifest entries for the Reference part.

- `topics.php`: topic key ⇒ `title`, `guide` (docs path or `pending:<phase>`), `intro` (one or two sentences), `members` (patterns: `Preflow\Media\*`, `fn:media_image`, `cmd:media:*`, `config:media.*`). Cover the spec's concept list (Build + Folio + Extend topics) so every entry has a home.
- Topic pages: the intro, the guide link (or "guide coming in phase N"), then the member entries grouped by kind, each linking to its package page anchor.
- `docs:check`: orphans (entries in no topic) and missing descriptions as errors/warnings; pending topics listed; exit non-zero on errors. The test runs the same check on the committed `index.json` + `topics.php`.
- [ ] Tests (Review Focus 4) with a small fixture index; the real check passes (no orphans) after filling `topics.php`.
- [ ] Commit: `feat(docs): topics, by-task reference and completeness check`
