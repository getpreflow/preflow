# preflow.dev Website Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** preflow.dev on Preflow 0.63 with Folio: a new home page and a `/folio` page built from Folio blocks, references as a Folio type, code shown from the starters' real files, a generated packages list, and screenshots and recordings made by a script kept in the repo.

**Architecture:** Task 1–2 add a small Folio extension to `preflow/starter-folio` and release it (0.63.1), because the Folio page shows it. Everything else happens in the website repository (`/Users/smyr/Sites/gbits/preflow-website`, GitHub `getpreflow/website`, branch `main`). It is built the way `smeyer.me` is built (`/Users/smyr/Sites/gbits/smeyer.me`), the closest existing Folio site: path repository to the monorepo with `"^0.63 || @dev"` constraints plus `deploy/server-composer.php`, a `site:seed` command that seeds an empty site, the `SiteScaffold` test trait, and that site's Deployer recipe. Starter code is copied into the repository by a console command (never pasted, never a Composer dependency: both starters autoload `App\`, which would collide with the website's).

**Tech Stack:** PHP 8.4+, Preflow 0.63 (core, routing, view, twig, components, htmx, data, auth, validation, form, folio, media, roles, i18n, devtools, testing), SQLite, Twig, HTMX, Deployer. Dev only: `chrome-php/chrome` driving the installed Google Chrome, and `ffmpeg` (`/opt/homebrew/bin/ffmpeg`) for recordings.

**Spec:** `/Users/smyr/Sites/gbits/preflow-framework/docs/superpowers/specs/2026-11-10-website-design.md`

## Global Constraints

- PHP 8.4+. No Node, no npm, no bundler, no build step in the site. The capture tooling is PHP (dev dependency) and is never needed to run or deploy the site.
- Preflow `^0.63` for every `preflow/*` package (`"^0.63 || @dev"` locally with the path repository, first alternative only on the server, exactly as `smeyer.me/deploy/server-composer.php`).
- Strict CSP with nonces stays; every new script and style works under it (inline JS/CSS only through `{% apply js %}` / `{% apply css %}` or nonce'd tags).
- Public pages stay cookie-free so the page cache can serve them: the session starts only under the Folio admin path.
- Code on the site is real code from the starters, read from `resources/starters/<starter>/` (synced copies). Never pasted into Folio, never simplified.
- Pictures (screenshots, recordings) are produced by `tools/capture` and can be retaken by running it again.
- Recordings: muted, looping, poster image, under about 2 MB each, never autoplaying for visitors who prefer reduced motion, never with sound.
- English only. The current look carries over: the colour tokens, font stack and dark/light themes of `app/pages/_layout.twig`.
- Navigation: Home · Docs · Folio · Packages · GitHub (`/`, `/docs/getting-started/installation`, `/folio`, `/#packages`, `https://github.com/getpreflow/preflow`).
- Placeholder hero headline: "Server-rendered PHP. Pages that don't break. A CMS when you want one."
- References (seeded): holz-objekte.org, BG Genius (boardgamegenius.net), languagecorner.ch, smart-stack.works, smeyer.me, preflow.dev.
- Never type, print or store the owner's password. Test logins are local test values only (as in `smeyer.me/tests/Support/SiteScaffold.php`).
- `composer test` green before any commit that a task ends with. Never run two test suites at once.
- Framework rules: anything general the website needs and the framework lacks goes into a framework package, not the website. If an implementer finds such a gap, stop and report it (NEEDS_CONTEXT) instead of working around it in the website.

## Review Focus

1. **A starter file a code block names no longer exists** after `starters:sync` (renamed in a later starter release): the block shows its error-boundary fallback, the page still renders 200, and a test lists every file the seeded content names and fails before deploy. Pinned in Task 5 and Task 7.
2. **An editor types a dangerous or wrong link** (`javascript:…`, `//evil.example`, `/\evil`) into any link field: it is not printed as a link. Pinned in Task 7 (`test_unsafe_links_are_not_printed`).
3. **A visitor who switched to the light theme** gets light pages from the page cache without a cookie and without a dark flash. Pinned in Task 3.
4. **Packagist is unreachable or answers garbage** during `packages:refresh`: the command fails with a message and leaves `resources/packages.json` unchanged. Pinned in Task 6.
5. **Old URLs** (`/docs/packages/skeleton`, `/api/source?…`) answer with a redirect or 404, never a 500 or a JSON error page. Pinned in Task 10 and Task 3.

### Task 8: Capture script

**Files:**
- Modify: `composer.json` `require-dev`: `chrome-php/chrome`.
- Create: `tools/capture/capture.php` (CLI: `php tools/capture/capture.php [--only=<id>]`), `tools/capture/shots.php` (the list), `tools/capture/README.md` (what it needs: Google Chrome, ffmpeg, Composer; how to run; how long it takes).
- Output: `public/captures/<id>.webp` (screenshots), `public/captures/<id>.mp4` + `public/captures/<id>-poster.webp` (recordings), `resources/seed/references/<slug>.webp`.

How it works:
1. Installs both starters fresh with `composer create-project preflow/<name> <tmp>/<name> "<version from resources/starters/<name>/VERSION>"` (runs their scripts: migrate + demo seed), reads the demo logins from the starters' seed files (`app/Seeds/demo-data.php` or wherever the starter keeps them: these are the starters' own test values; never other credentials).
2. Starts each with `php -S 127.0.0.1:<free port> -t public` (stops them by the PIDs it started, never by pattern).
3. Drives headless Chrome at 1280×800, light theme of the starters, through the steps in `shots.php`. A shot is `['id' => ..., 'starter' => ..., 'type' => 'screenshot'|'recording', 'steps' => [...]]` with steps `goto`, `login`, `click`, `type`, `wait`, `scroll`. Recordings take frames at 10 fps and encode with `ffmpeg -c:v libx264 -pix_fmt yuv420p -movflags +faststart -crf 28` (lower quality until each file is under 2 MB), plus the first frame as poster.
4. Reference screenshots: each published reference URL's home page at 1280×800, viewport only.
5. Exits non-zero naming the shot that failed; leaves earlier outputs of other shots in place.

Shots (ids are what Tasks 7 and 9 reference): `code-model` (job page), `code-page` (`/jobs`), `code-component` (recording: typing in the search, results swap), `code-error-boundary` (`/about-error-boundaries`), `code-api` (`/api/jobs` JSON in the browser), `folio-job-form` (recording: starter-folio, Folio jobs list → open a job → the form), `folio-page-first` (recording: open the home page in Folio, edit the hero headline in the preview, publish), `folio-list-first` (recording: add a job in its list, publish, open `/jobs`, the job is there), `folio-publish`, `folio-roles`, `folio-media`, `folio-translations`, `folio-seo`, `folio-redirects` (screenshots of those Folio screens; if the starter has no second language, the translations shot shows Folio's translation screen as it is), `folio-extension` (the company list with "Open jobs" and the dashboard notice).
