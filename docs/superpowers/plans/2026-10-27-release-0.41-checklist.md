# Release 0.41 checklist

Atomic version check on save and `Publisher::stateWith`, from the holz-objekte.org follow-ups (Folio
autosave racing a site's own version-checked save of the same record).

- **preflow/data:** `Preflow\Data\VersionedStorage` (extends `StorageDriver`) with
  `saveIfVersion($type, $id, $data, $versionField, $expected, $idField)`: writes only when the stored
  version is `$expected` (missing or empty counts as 0; a missing record is inserted for 0, a
  concurrent insert loses). `PdoDriver` (SQLite, MySQL) claims the row with
  `UPDATE … SET _version = :next WHERE id = ? AND _version = ?` in a transaction (a caller's open
  transaction is used as it is), then writes as `save()` does; MySQL without `FOUND_ROWS` is covered by
  a follow-up `SELECT`. `JsonFileDriver` checks and writes under `{type}/.lock`.
  `DataManager::saveTypeIfVersion($record, $expected, ?$next = null, $versionField = '_version',
  $validate = true, $rules = [])` returns `bool`; any other driver gets a read, compare and write.
- **preflow/folio:** `Publisher::saveDraft()` writes through `saveTypeIfVersion()`: a save landing
  between its check and its write gives `VersionConflict` (with a loaded version) or is retried on the
  newer version (without one, up to 3 times). Autosave and the form save use it; their conflict
  responses are unchanged. `Publisher::stateWith($working, ?$snapshot)` (no read; `state()` uses it),
  `Publisher::states($type, ?array $ids = null)` (one snapshot query either way).
- **Not changed:** `Publisher::publish()` still writes the working copy back unchecked (roadmap
  follow-up: checking it would throw from the scheduler, the CLI and site importers). Done in
  0.41.1 as an optional loaded version.

Constraints (the packages' `ComposerConstraintsTest` pins them):

- `preflow/folio`: requires `preflow/data` `^0.41 || @dev`, conflicts with `preflow/data` `<0.41`.

## Upgrading to 0.41: notes for site owners

- **No migration, no config change.** `composer update 'preflow/*'`.
- **Folio needs `preflow/data` 0.41** (conflict below).
- **Behaviour:** a Folio save that loses a race to another save now fails with the usual conflict
  ("Someone else changed this record") instead of overwriting it. `saveDraft($record, null)` can now
  throw `VersionConflict` in rare cases: when others save the record during each of its three tries,
  and (0.41.1) inside a caller's transaction, where the retries reread the same snapshot and one lost
  race is enough.
- **JSON storage:** version-checked saves leave a `.lock` file in each type's folder (hidden, never read
  as a record; safe to delete). Sites that keep JSON content in Git or SSH-sync it should ignore it:
  `.gitignore` line `**/.lock` in the content folder (or `storage/data/**/.lock` from the site root),
  and exclude `.lock` from the sync.
- **Site code:** a version-checked write of a publishing type keeps calling
  `Publisher::saveDraft($record, $loadedVersion)` (now atomic). Other types:
  `DataManager::saveTypeIfVersion($record, $loadedVersion)`. `Publisher::stateWith()` replaces a
  second snapshot read where the site already holds the snapshot.
- **Custom storage drivers** keep working; implement `VersionedStorage` to make their saves atomic.

# Patch 0.41.1

Three findings in 0.41.0's compare-and-set saves (review after the release), plus small follow-ups.

- **preflow/data, lost update inside a caller's transaction (MySQL/MariaDB):** under REPEATABLE READ
  a caller's transaction (Folio's `RecordDeleter::transaction()` around `saveDraft($r, null)`) fixes
  its snapshot at its first read; after another connection commits, the claim `UPDATE` (a current
  read) matches nothing, but the follow-up `SELECT` (a consistent read) saw the old version and the
  save overwrote the other write. The `SELECT` now runs only for a write keeping the version (the one
  case it exists for, MySQL without `FOUND_ROWS`) and is a locking read: `Dialect::lockingRead()`
  (`FOR UPDATE` on MySQL, nothing on SQLite).
  MariaDB with `innodb_snapshot_isolation` (on by default since 11.6) refuses such a write itself
  (error 1020). SQLite in WAL mode refuses it too (`SQLITE_BUSY_SNAPSHOT`, "database is locked"); in a
  caller's transaction both stay exceptions (the transaction can write nothing more and must roll
  back). A failed statement's cursor is closed now, so SQLite ends that stale read once the caller
  rolls back (the exception's trace held the statement open).
- **preflow/data, a stored empty `_version`:** the claim for 0 is
  `(_version IS NULL OR _version = '' OR _version = ?)`, as JSON and the fallback treat `''`. Only
  canonical integer strings match on SQL (`'05'`, `'5.0'` do not; JSON reads them as 5);
  `saveIfVersion()` writes an integral version canonical (`'05'` → `'5'`).
- **preflow/data, concurrent first saves (MySQL):** the claim of a missing row took a gap lock in each
  writer, and their two INSERTs deadlocked (40001, a 500). A first save (`$expected` 0) now reads
  whether the row exists and inserts first; a duplicate key (a concurrent first save won) falls back
  to the claim. An existing row is claimed without an INSERT (an INSERT on it would take a shared lock,
  and two such writers would deadlock upgrading it). A deadlock (40001) or MariaDB's 1020 is a lost
  race (`false`) when the driver opened the transaction, rethrown in a caller's transaction.
- **preflow/data:** `saveTypeIfVersion()` on a driver without `VersionedStorage` raises
  `E_USER_NOTICE` once per driver class; a failed save removes a version key the record did not have
  (`DynamicRecord::remove()`, new).
- **preflow/folio:** `Publisher::states($type, $ids)` reads 500 ids per query.
- **preflow/folio, version-checked publish (the 0.41 roadmap follow-up):**
  `Publisher::publish($record, $by, ?int $loadedVersion = null)`. With a version it validates,
  claims the working copy (compare-and-set, version kept), then writes the snapshot and the
  revision, in one transaction on SQL storage (a caller's open one is used); a stale version throws
  `VersionConflict` before any snapshot is written, and the record is left as it was. `null` is
  0.41.0's unchecked write (scheduler, `folio:publish`, importers building records without
  `_version`). `discard()` and `restore()` take an optional loaded version too (Folio's own buttons
  keep calling them without). Folio's form publish passes the version its draft save just wrote; a
  save landing in between gives the usual conflict form (409; the draft save stays, nothing goes
  live). **The version is not bumped by publish:** it changes no content (only clears
  `_publish_at`), so an editor or a site panel holding the version stays valid, and Folio's form and
  autosave keep working after a publish unchanged.

No constraint changes (folio keeps `preflow/data` `^0.41 || @dev`; `composer update 'preflow/*'` gets
both patches).

## Upgrading to 0.41.1: notes for site owners

- **No migration, no config change.** `composer update 'preflow/*'`.
- **Behaviour:** inside your own transaction a Folio save that lost a race no longer overwrites: it
  conflicts (`VersionConflict`, also from `saveDraft($r, null)`, whose retries reread the same
  snapshot) or, on MariaDB 11.6+ and SQLite, the database's error is thrown and your transaction has to
  roll back. Outside a transaction nothing changes, except that two simultaneous first saves of one new
  record give a conflict instead of a 500.
- **Records with `_version` = `''`** can be saved from Folio again.
- **Publishing from Folio's form** now conflicts (409, "Someone else changed this record") when
  another save lands between the form's draft save and its publish, instead of overwriting it.
  `publish()` does not change `_version`. Site code that publishes a record an editor loaded can
  pass the version: `$publisher->publish($record, $by, $loadedVersion)` (catch `VersionConflict`);
  without it nothing changes (scheduler, CLI, importers).
- **JSON content in Git or SSH-synced:** ignore `{type}/.lock` (`**/.lock` in the content folder's
  `.gitignore`).
- **Custom storage drivers** without `VersionedStorage` now raise one `E_USER_NOTICE` per driver class
  on a version-checked save (non-atomic fallback). **Custom `Dialect` implementations** add
  `lockingRead(): string` (`' FOR UPDATE'`, or `''`).
