## Global Constraints

- **Guide rhythm** (GuideRhythmTest already covers `docs/folio/` and `docs/extend/` — extend it if it doesn't): six `##` sections in order `In one sentence`, `See it work`, `How it ties in`, `Step by step`, `Good to know`, `Go deeper`; ≥1 code example; ≥1 figure. "Go deeper" links the topic page (`/docs/reference/topics/<key>`), the main reference entries used, the next guide.
- **Extend guides (spec Goal 4)** each cover, in the rhythm: what the extension point does and its interface; the contract (what an implementation must guarantee); a small real worked example; how to test it (the contract suite where one exists, otherwise a `preflow/testing` test case). Worked examples are run: write them in a scratch app on the site's Preflow version and make them pass before putting them on the page.
- **Folio guides** show code from `preflow/starter-folio` only through the ```starter``` fence (add files via `config/starters.php` + `php preflow starters:sync`); admin screens as captures (`tools/capture`, both themes).
- **Truth:** every statement true for Preflow 0.64.0 — verified against the package READMEs and code in the monorepo (read-only from the website tasks).
- **Completeness:** each guide covers its topic's members well enough that a reader knows what exists and when to use it; nothing in the topic left without at least a pointer.
- **Voice:** as in `docs/understand/*`, `docs/start/*` and `docs/build/*` — plain, friendly, short sentences, concrete; glossary terms linked on first use (add glossary entries as needed).
- **Old pages:** when a guide replaces `docs/packages/{view,twig,blade,folio}.md`, delete the file, remove it from "Older pages", add a 301 in `ContentSeeder::redirects()` (applied on already-seeded sites too).
- **Framework rules:** features in packages behind public interfaces; Folio only the UI adapter. Never two test suites at once. Commit locally only (the controller pushes, releases, deploys).
- Strict CSP, cookie-free, both themes, 375 px.

## Review Focus

1. A contract suite that only passes because it mirrors one adapter's quirks (e.g. asserting `hx-*` attribute names, or SQLite's NULL ordering) — a second, independent implementation must be able to pass it.
2. An Extend worked example that wouldn't run as shown (missing `use`, wrong registration, a method the interface doesn't have).
3. A Folio guide describing an admin screen or JSON key that doesn't exist in 0.64 (field options, block attributes, publish states).
4. Defaults stated as always true (Folio config options, storage per type, staff vs. member guards).
5. Broken links/anchors after the `packages/*` redirects and the removal of the "Older pages" group.

**Interfaces (Produces — the Extend guides document these):**
- `TemplateEngineContract`: `abstract protected function createEngine(string $templateDir): TemplateEngineInterface;` `abstract protected function fixture(string $name): string;` — returns the engine's source for the named fixtures `variable` (prints `name`), `escaped` (prints `html` escaped), `raw_function` / `escaped_function` (calls the registered function `shout`), `global` (prints global `site`), `namespaced` (includes `@lib/part`), `part`. The suite writes the fixtures under the engine's `getTemplateExtension()`. Tests: render with context; output escaping by default; `addFunction` with `isSafe` true/false; `addGlobal`; `exists` true/false; `addNamespace` first-registered path wins; rendering a missing template throws.
- `HypermediaDriverContract`: `abstract protected function createDriver(): HypermediaDriver;` `abstract protected function fragmentRequest(ServerRequestInterface $request): ServerRequestInterface;` (marks a request the way the driver's client does) `abstract protected function effects(): array;` (the response-side effects the driver recorded, as strings). Tests: `actionAttrs` names the URL, the method and the target id somewhere in its values and keeps `$extra`; `listenAttrs` names the event and the URL; attributes render escaped (`HtmlAttributes`); `isFragmentRequest` false for a plain request and true for `fragmentRequest(...)`; `triggerEvent`/`redirect`/`pushUrl` each show their event or URL in `effects()`. No attribute names or header names asserted.
- `StorageDriverContract`: `abstract protected function createDriver(): StorageDriver;` `abstract protected function createType(string $type, array $fields): void;` (`$fields` = name => `string|number|boolean|json`; SQL drivers create the table, e.g. via `RecordTableSync`; JSON does nothing). Tests: save/findOne round trip per field kind (incl. null, unicode); save twice updates; `exists`; `delete` (and deleting a missing id is not an error); a custom `$idField`; `findMany` with each whitelisted `where` operator, `IN`/`NOT IN` (incl. empty lists), `where(x, null)`, `orWhere` groups, order asc/desc on strings and numbers, limit/offset, `ResultSet` total; numeric ids get `lastInsertId()` where the driver supports auto ids. Where SQL-only (`rawQuery`), the suite asks `protected function supportsRawQuery(): bool` (default true) and skips with that reason.
- The existing data-package `WhereScenarios`/`OrGroupScenarios` stay; the contract reuses their expectations where they match, no copies of private fixtures.

### Task 5b (framework, inserted 2026-11-11): the big three become pluggable — release 0.65.0

Ruling (controller, from Task 5's findings): in 0.64 a third-party template engine, hypermedia driver or storage driver can't be registered — `Application::createTemplateEngine()` is a closed match on twig/blade; the `hd.*` helpers, `ComponentEndpoint` (effects via reflection on `HtmxDriver`'s private `ResponseHeaders`, `HX-Target` read directly) and the form helpers hold the boot-time `HtmxDriver`; `config/data.php` drops unknown driver names silently; `Grammars::for()` knows only sqlite/mysql and `QueryCompiler` hard-codes `LIKE`. The spec (Goal 4, owner: "someone could bring in Datastar or PostgreSQL") and the framework rule ("anything general the docs need goes into the framework in a release") require these to be real extension points. Cost if wrong: one minor release of API the owner may want shaped differently.

**Files:** framework monorepo, packages `core`, `view`, `htmx`, `components`, `form`, `data`, `testing` (contract suites updated where interfaces grow), READMEs of those packages (short sections), ROADMAP (0.65.0 entry with Upgrading notes).

**Decisions (binding):**
- **Template engine:** `app.engine` accepts `'twig'`, `'blade'`, or a class name implementing a new `Preflow\View\TemplateEngineFactory` (`create(TemplateEngineContext $context): TemplateEngineInterface`), where `Preflow\View\TemplateEngineContext` is a readonly value object carrying what core passes to the built-ins today (template dirs, `AssetCollector`, debug flag, a cache path under storage, `GeoCollector`, `SeoContext`, `LiveParts`, `PageCache`). The factory's engine is built at the same point as the built-ins and gets the packages' template functions, so file pages and components render through it. Unknown names still throw, listing the accepted forms. The built-ins may stay as they are or become factories — implementer's choice, no behaviour change for twig/blade.
- **Hypermedia driver:** one driver per app, resolved from the container (`HypermediaDriver` binding; config key `app.hypermedia` naming a class of a `HypermediaDriver` that the container builds, default HTMX). The `hd.*` helpers, `ComponentEndpoint` and the form helpers use that binding, never `HtmxDriver` directly. Response effects get a public path: the driver applies them to the response (e.g. `HypermediaDriver::applyEffects(ResponseInterface $response): ResponseInterface` or a small `ResponseEffects` interface the driver exposes), and the target id of a fragment request comes from the driver (e.g. `fragmentTarget(ServerRequestInterface): ?string`). Interface additions are allowed in this 0.x minor; `HtmxDriver` implements them with today's behaviour; `HypermediaDriverContract` tests the new methods driver-neutrally; the scratch `DataAttributeDriver` worked example (`/private/tmp/claude-501/-Users-smyr-Sites-gbits-crelish-spielegesellschaft/c045099d-4ae3-4489-89f6-57a7940a9547/scratchpad/contract-examples/`) is updated and passes. `Component::setRootAttribute()` also accepts Datastar-style names (`data-on:click`, `data-on:click__debounce.500ms` — `data-` followed by `[a-z0-9:._-]+`), still rejecting anything that could break the attribute.
- **Storage driver:** a `config/data.php` driver entry may name a class: `'drivers' => ['pg' => ['driver' => App\PgDriver::class, ...options]]` — built through the container (or a `StorageDriverFactory` interface with `create(array $options): StorageDriver`, implementer's choice, one of the two); an unknown driver name throws at boot with the accepted forms. Migrations: a driver supplies its grammar (a `ProvidesGrammar` interface on the driver, or `Grammars::register(name, Grammar)` — one of the two), so `RecordTableSync` and `migrate` work for a new SQL database. `QueryCompiler` asks the `Dialect` for case-insensitive matching (`Dialect::likeOperator(): string` or equivalent — `LIKE` for sqlite/mysql, `ILIKE` possible for PostgreSQL). `StorageDriverContract` keeps passing for SQLite, MySQL, JSON.
- No PostgreSQL driver ships; the docs keep it a path — now one with no framework blockers.

### Task 5c (framework, inserted 2026-11-11): Folio follow-ups from the Folio guides — same release 0.65.0

Owner ruling (2026-11-11): "No workarounds. If a framework change is needed to achieve the goals and vision, that is what we will do." The Folio guides currently warn about or explain around these; fix them instead.

**Decisions (binding):**
- **Who may sign into Folio.** Folio signs staff in through `folio.guard` (new config key; default: the app's default guard, as today). At boot, if that guard declares a `population` other than `staff`, Folio refuses with a clear `RuntimeException` naming the guard, its population and what to configure (a staff guard, as in starter-folio). A guard without a population keeps today's behaviour (smeyer.me, smart-stack.works and preflow.dev run that way — they must keep working unchanged). `preflow/starter` declares `'population' => 'employers'` on its employers guard, so adding Folio to it as-is fails loudly instead of letting employers in. Check members' `Viewer` (0.63.2 staff rule) and `markStaffGuard` stay consistent with `folio.guard`.
- **Uninstalling an extension.** New command `folio:extensions:uninstall <name>`: refuses while the extension is enabled or extended by another, asks for confirmation (`--force` skips it), calls `Extension::uninstall()`, then clears its installed state; nothing calls `uninstall()` implicitly. Document in the Folio README.
- **Folio on an app with its own template engine.** Folio's own templates (the admin, and its fallback frontend templates such as `@folio/frontend/page.twig`) render through a Twig engine Folio owns, whatever `app.engine` is; app templates (types' frontend templates in the app) render through the app's engine with the `folio_*` functions available there. Twig/htmx apps see no change. Prove it with the factory-built `PhpTemplateEngine` from the contract examples in a scratch starter-folio.
- **README fixes found by the guides:** Folio README — table sync works on SQLite and MySQL; only the dashboard is overridable; screens and record actions declare their permissions themselves (bulk actions don't); BeforeSave/AfterSave also run on the bulk "Set …" save. Also the relation column kind reads `relation.multiple` (FieldKinds + RelationFieldType::columnKind), and `folio:assets:import --dry-run` doesn't count rows it wouldn't change (and a real run doesn't rewrite them).
- **starter-folio:** revision authors shown by name, not raw id; `staff:create` accepts any role that exists (rbac roles included) — and its own staff table no longer clashes with rbac's (rename or share; implementer decides with the ROADMAP's earlier note on the clash, and must keep `composer test:starters` green); `create-project` runs `folio:extensions:apply` so a fresh install shows `jobs` installed.
- **Admin layout without GEO alternate:** signed-in admin pages don't carry the Markdown alternate link.
