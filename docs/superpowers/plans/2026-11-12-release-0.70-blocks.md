# Release 0.70 — preflow/blocks, and the remaining rules out of Folio Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Blocks are their own Folio-free package; redirect write rules, translation-override checks and asset alt-text translation live in their cores; the 0.69 aliases go (spec D1, D7 rest; owner: "blocks should be their own package … clearer how to extend them and bring in own block types").

**Architecture:** A new package `preflow/blocks` (`Preflow\Blocks`) holds the block model, registry, discovery and renderer; it asks two small interfaces for what it needs from outside (the content locale, rich-text cleaning) with plain defaults, and Folio binds its own. Folio keeps the blocks field type and the editor. Routing gets `RedirectRules`, i18n gets the override check, media gets an alt-text `TextSource`. Publishing and the shared record write path are release 0.71.

**Tech Stack:** PHP 8.4, PHPUnit 11, Twig/Blade, the Preflow monorepo; the six sites.

**Spec:** `docs/superpowers/specs/2026-11-12-package-audit-fixes-design.md` (D1, D7). Evidence: `.superpowers/audit-2026-11-12/report-folio-src.md` (FOLIO-4, FOLIO-5), `report-folio-ui-starters.md` (STARTERS-1).

## Global Constraints

- Owner's rules: no workarounds; framework = abstractions only; Folio is the UI adapter; mails never mention Folio.
- `packages/blocks/src` contains no `Preflow\Folio\` reference; blocks requires core, components, data and view at most (no folio, no i18n unless needed for the default locale).
- Stored data keeps its shape: block JSON in records (`_block`/`_id`/fields), existing block keys, `extra.folio.blocks` still read for one release (with a deprecation line), `config/folio.php` `blocks` read for one release.
- Moved public classes keep class aliases for one release (`legacy-aliases.php`); the template function `folio_blocks()` stays as an alias of the new `blocks()` for one release.
- The six sites behave the same; their code moves to the new names in this release (Task 5).
- Tests per package (`vendor/bin/phpunit --testsuite <Pkg>`); full suite at the release; never two test runs at once; no background test loops left running.

### Task 2: redirect write rules in routing

- Create `Preflow\Routing\Redirect\RedirectRules` holding the rules from `packages/folio/src/Http/RedirectsController.php` `save/checkAddress/targetedBy/checkTarget/redirectsAt/entryBelow` (no chains, a page wins over an exact entry, no area over the whole site, target not inside its own area, a record target must be live, keep-the-rest rules, the not-found row forgotten on save). It works on `RedirectStore` plus two small interfaces for what only the site knows: `PageExists` (is there a page at this path) and `TargetIsLive` (is a record target published). Folio binds them.
- `RedirectEntries::save()` (Folio's store) and the controller both go through `RedirectRules::check(array $entry, ?array $existing): RedirectErrors` (field → message key); the controller maps errors to texts.
- Tests: Review Focus 3; every existing redirect controller test stays green.
- Commit `refactor: redirect rules live in routing`.
