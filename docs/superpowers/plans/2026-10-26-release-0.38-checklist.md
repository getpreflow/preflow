# Release 0.38 checklist

The members split. `preflow/members` is a core without Folio and rbac: registration with a
confirmed address, sign-in and sign-out, forgot and reset password, the account page with
self-deletion, the member mails, `members:prune` and `members:decide`. It requires auth, core,
data, routing, i18n, notify, validation, view and devtools. Folio carries the members admin
(Members list, Decision panel, Settings → Members, the menu section, the rbac roles) and switches
it on when `preflow/members` is installed, as it does for media. On top: a checked `next` through
registration and confirmation (`next.allow`), accounts a project creates with an already-verified
address (`emailVerified`, `SignIn::in()`), hooks (`MemberEvents`), self-deletion through the
delete plan with self rules (`onSelfDelete` in data), rehash on sign-in in auth (members and Folio
staff), a default landing at `GET {path}`, a primary link (`action`) for the mail layout and an
admission that composes the name (`ComposesName`). The default admission is now
`AcceptOnConfirm`; `OwnerApproval` stays, opt-in.

The work is on `feat/members-split`. The release is prepared: members, Folio, auth and data
READMEs, roadmap entry (and the "Later: SEO and GEO" section), spec
(`docs/superpowers/specs/2026-10-26-members-split-design.md`), plan
(`docs/superpowers/plans/2026-10-26-members-split.md`), constraints. It is not merged, pushed or
tagged; the owner decides.

Constraints (each conflict matches its require's lower bound; the packages'
`ComposerConstraintsTest` pins them):

- `preflow/members`: auth `^0.38` (`Preflow\Auth\Record\RecordUser(Provider)`, `RoleField`,
  `PasswordRehash`, `Access::resolver()`), core `^0.38` (`bootAuth` binds
  `RecordUserProvider::factory()`, so `config/auth.php` builds record users without Folio), data
  `^0.38` (`DeletedBy`, `onSelfDelete`, `ensureTypeRegistry()`), routing `^0.38` (`RoutePattern`),
  i18n `^0.38` (raised with the release; no new i18n API is used, `^0.37` would do); conflicts
  `<0.38` for each, and with `preflow/folio` `<0.38` (an older Folio has no members admin and the
  older members package shipped its own). `preflow/folio` and `preflow/rbac` moved from `require`
  to `suggest`. Notify, validation, view and devtools keep their bounds.
- `preflow/folio`: auth `^0.38` (the moved record user classes, `PasswordRehash`), data `^0.38`
  (`DeletedBy` in `RecordDeleter`); conflicts `<0.38`, and with `preflow/members` `<0.38`
  (members is a `suggest`, not a `require`). Core stays `^0.34`, i18n and validation `^0.37`,
  media `^0.36`.
- `preflow/core`: conflicts with `preflow/auth` `<0.38` (new; core requires no auth, but
  `bootAuth` calls `Preflow\Auth\Record\RecordUserProvider::factory()` when auth is installed).
  New `packages/core/tests/ComposerConstraintsTest.php` pins it with the existing data `<0.28`.
- `preflow/auth`, `preflow/data`, `preflow/routing`: unchanged. auth's record provider uses only
  data API from before 0.14 (`findIn`, `queryIn`, `saveType`); data and routing gained API but
  call nothing new elsewhere.
- rbac and codes: unchanged (folio and i18n `^0.37`; neither calls a moved or new API).
- `composer.lock` refreshed for the path packages only (`composer update preflow/core
  preflow/folio preflow/members`): their new requires, conflicts, suggests and declarations
  (members' `extra.folio.extension` gone, `DecideCommand` listed); no third-party package

mechanisms only; project features stay in projects; a package's official admin UI lives in Folio.
Every members feature, sorted. "Stays" means generic. Nothing was changed by the audit itself:
the moves it found are not trivial (they change public pages, mails or a site's admin), so they
are findings for the owner (F1–F8 below).

### Findings for the owner

- **F1. The member pages' styles are smart-stack.works' design.** `_card.twig` styles the pages
  with smart-stack's tokens and spacing (`--paper`, `--rule`, `--ink`, `--font-mono`,
  `.section-inner`, `padding: 8rem 2rem 6rem`, an uppercase mono tag), and the new
  `_layout.twig` defines those tokens so the pages work without Folio. Generic would be a neutral,
  minimal style with documented custom properties (or a `members.css` a site replaces). Changing
  it changes every site's public member pages (smart-stack.works relies on it; the 0.36 register
  snapshot is byte-pinned). Proposal: a later release, with a release note.
- **F2. The mail accent default `#d42a34`** (the red of `_layout.twig` too) is a site colour.
  Generic: a neutral default (dark grey) or none. smart-stack.works uses its own mail layout, so
  only sites on the shipped layout without `mail.accent` would see the change.
- **F3. "Open in Folio: {folio_url}"** in `mail.notice.body` and `mail.deletion_refused.body`
  (en/de/fr) names Folio for any bound `MemberLinks`, and the placeholder is `{folio_url}`.
  Generic: wording like "Decide here: {decision_url}" (keeping `{folio_url}` as an alias for one
  release). Changes the owner's mails on Folio sites (a site test may pin the wording). Owner's
  wording call.
- **F4. `Links::folioMember()`** (and its folio prefix) is deprecated and unused by the package;
  smart-stack.works' `MembersServiceTest::test_links_never_use_request_host` still calls it. Remove
  in 0.39 after the site's test moves to `FolioMemberLinks` or drops that assertion.
- **F5. The members admin's texts (`members-admin`) are shipped by the members package**
  (`packages/members/lang/*/members-admin.php`, declared in its `composer.json`), while the admin
  itself is Folio's. By the rule they belong to Folio (`packages/folio/lang`, Folio declaring the
  group, the group name kept). A site's overrides keep working because the group name stays.
  Not trivial: translation declarations, `translations:check` and both packages' tests move.
- **F6. Consent is always required.** The register form always has the consent checkbox and
  refuses a registration without it; a site can reword it (`consent_text`, `privacy_url`) but not
  drop it (e.g. a site that asks consent elsewhere, or BG Genius's invitation flow, which bypasses
  the form anyway through `emailVerified`). Option: `consent => false`. Keep as is unless a project
  needs it.
- **F7. The refusal mail names pointing types by key** (`order: 1`), not by label: labels may be
  translation keys only Folio resolves. Option: a `MemberLinks`-like hook for labels, or Folio
  passes resolved labels. Cosmetic.
- **F8. `MembersConfig`'s docblock** says the defaults are smart-stack.works' values. They are
  ordinary values (throttles, retention, password length); only F1/F2 are site-specific. Reword
  with F1/F2.

### Known open items (deferred from the reviews)

- **`FolioMemberLinks` falls back to `http://localhost`** when `app.url` is unset, so the owner's
  mail links to localhost on a site without `app.url`. Option: no link (`null`) without `app.url`.
- **rbac's `RoleList` is still a separate roles parser.** `Preflow\Auth\Record\RoleField` uses
  the same rule and RecordUser and members read roles through it; rbac should use it too, so the
  rule lives in one place.

## Upgrading to 0.38: notes for site owners

Also in the members README ("Upgrading to 0.38"), the Folio, auth and data READMEs. Put these in
the release notes.

- **Default admission is `AcceptOnConfirm`** (was owner approval): a confirmed address makes a
  member at once. `OwnerApproval` stays, opt-in: `'admission' =>
  Preflow\Members\Admission\OwnerApproval::class` in `config/members.php`. smart-stack.works and
  holz-objekte.org set their admission explicitly and are not affected.
- **Default layout:** on a site **without Folio** the member pages use the package's standalone
  `@members/_layout.twig`; a Folio site keeps `@folio/frontend/_site.twig` (Folio supplies that
  default through `MembersDefaults`). A site with its own layout sets `layout`. smart-stack.works
  is a Folio site and keeps its layout (its suite is unchanged at 1781 assertions).
- **Members no longer requires Folio or rbac.** Both are suggestions. Folio carries the members
  admin (it still needs the `rbac` extension enabled, as before) and switches it on when Composer
  lists `preflow/members`. Run `composer update 'preflow/*'`: until then a site's `installed.json`
  still names `Preflow\Members\Extension`, which Folio ignores. `folio-extensions.cache` rebuilds by
  itself. The extension name `members`, the type keys `member` and `members_settings`, the
  permissions and the roles stay.
- **`RecordUserProvider` moved to auth:** `Preflow\Auth\Record\RecordUserProvider` and
  `Preflow\Auth\Record\RecordUser`. The old names `Preflow\Folio\Users\RecordUserProvider` /
  `RecordUser` are class aliases for one release; a `config/auth.php` naming the old provider is
  built by Folio and logs a deprecation (the debug toolbar); the old `RecordUser` alias logs none.
  The constructor changed: `new RecordUserProvider($dm, $catalog, …)` with a `TypeCatalog` no
  longer works (the config path is fine). smart-stack.works' and holz-objekte.org's `config/auth.php`
  name the old class: switch to the new name before 0.39.
- **A type registry on sites without a models directory:** on a site with `config/data.php`
  (so a `DataManager` is bound; without one members defines nothing) where no `config/models` (or
  `data.models_path`) directory exists, the data layer used to have no type registry. Once
  `MembersServiceProvider` boots, members creates one (`DataManager::ensureTypeRegistry()`, on
  the models path, which is not created) to define its `member` type, and binds it in the
  container. On such a site `DataManager::getTypeRegistry()` no longer returns null and
  `$container->bound(TypeRegistry::class)` is no longer false after members' boot. Code that
  took "no registry" to mean "no dynamic types" now sees one, holding `member` only; dynamic
  type APIs (`findType`, `queryType`, `deletePlan`) work instead of throwing "TypeRegistry is not
  configured". Code that checked earlier in the boot (Folio's register-time models check) keeps its
  earlier view. An existing registry is never replaced.
- **Rehash on sign-in:** members and Folio staff logins store a fresh hash when the stored one is
  outdated (`$1$` MD5-crypt, an older bcrypt cost); sessions survive. Nothing to do.
- **Roles are read by one rule** (`RoleField`): a JSON string nested in a list, ints and
  `"a,b"` inside a list are now unpacked as rbac reads them.
- **`next`:** the default is unchanged (member pages only). `config/members.php` `next.allow` (a
  list of site path prefixes) widens it; an entry that is no site path is a boot error. `next`
  now also survives registration and confirmation.
- **`preflow migrate` on SQL storage:** the member type gains the hidden field `next`. Until the
  column exists a registration that carries a valid `next` fails on insert; registrations without
  `next` are unaffected. smart-stack.works stores members on `sqlite`: run it after deploy.
- **`onSelfDelete`:** relations may declare a rule for a person deleting their own record
  (`DeletedBy::Self`); unset follows `onDelete`, an invalid value is a boot error like an invalid
  `onDelete`. `DataManager::deletePlan()` takes a fourth argument `DeletedBy`.
- **`Members::delete()` returns a `DeletionResult`** and goes through the delete plan with the
  self rules (before: `deleteType()`, relations ignored). A `restrict` relation now keeps the
  account: the member reads that the site was told (409) and the owner gets a notice at
  `notice_email`. `members:prune` counts kept accounts (`; kept N (…)`, only when N > 0). On a
  Folio site the deletion reaches published snapshots. Folio's record hooks (`#[AfterDelete]` on
  admin types) do not run for records a member's deletion detaches or deletes (holz-objekte.org
  releases member uploads in one: check before removing its workaround).
- **`MemberEvents`** is new (registered, confirmed, decided, signed in, deleting, deleted,
  deletion refused). `Members::register()` gained `emailVerified:` and `request:`; the member
  controllers' constructors changed (autowired).
- **`GET {path}` (e.g. `/konto`) has a default landing** where sites had a 404. A site route on
  that path wins: a page file, an attribute route or a dynamic `/{slug}` route that matches the
  path. Only routes registered before members boots count: a provider that adds the same path must
  be listed before `MembersServiceProvider`, or the landing shadows it. smart-stack.works
  (`/tools`) and holz-objekte.org (`/konto`) have their own pages.
- **`ComposesName`:** an admission may compose the stored name; the register form then has no
  name field. Existing admissions are unchanged.
- **Mail `action`:** the confirm, reset and existing-account mails pass `action` (`{label, url}`)
  to the mail layout; the shipped layout shows a button and the URL. A site's own layout that
  ignores `action` sends the same mail as before. New keys `mail.{confirm,reset,existing}.action`.
- **Owner notice without Folio:** the notice mail's link comes from a `MemberLinks` binding (Folio
  binds the member's edit page). Without one the notice uses the new
  `mail.notice.body_without_link`; a site that overrode only `mail.notice.body` gets the package's
  text without the link there.
- **`Links::folioMember()` is deprecated** (unused by the package) and goes in 0.39.
- **New `members:decide <email> accept|decline`** for owner approval without Folio.
- **New texts** in the `members` group (landing, refusal messages, mail actions, refusal mail) in
  en/de/fr; German keeps "Sie". No existing text changed.
