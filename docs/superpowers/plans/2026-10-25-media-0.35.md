# Media 0.35 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The 0.35 half of media release 2: replace with versions, extra asset fields, colour management to sRGB, PDF previews and image colours. All of it lives in the `preflow/media` core, and Folio only adds UI. Released as v0.35.0.

**Architecture:**
- `Asset` gains versioning, preview, colour and extra-field data, stored as columns of the asset type.
- `MediaLibrary` gains `replace()`/`restore()`/`versions()` and `query()`.
- The image pipeline gets a colour-management step (Imagick plus ICC) used only for sources that need it.
- A `PreviewRenderer` interface gets a PDF implementation, and a colour extractor fills the colours.
- Folio's library controller and panel add the buttons, fields, filters and swatches.

**Tech Stack:** PHP 8.4, PHPUnit 11, Imagick (ImageMagick 7 with lcms), GD, Poppler/Ghostscript, Twig.

**Spec:** `docs/superpowers/specs/2026-10-25-media-release-2-design.md`. Read the "Design — 0.35" and "Settled details" sections, which bind; the 0.36 parts are out of scope.

## Global Constraints

- **Owner's rule:** every capability is in `packages/media/src` (no `Preflow\Folio` there; `NoFolioDependencyTest` stays green). Folio only adds UI and calls the core.
- **Nothing changes for untouched assets:**
  - release 1's byte-identical fixture (`packages/folio/tests/Integration/AssetFrontendTest.php`) stays green, unchanged;
  - existing records read as version 1, unedited, without colours;
  - sRGB and untagged images keep using today's backend (GD when it can write WebP) and produce the same files.
- **Version 1 keeps today's names:** `Y/m/{id}.{ext}`, variants `{id}-{w}.{fmt}`. Version n ≥ 2 is `Y/m/{id}-v{n}.{ext}`, variants `{id}-v{n}-{w}.{fmt}`.
- **Version files:**
  - stored in `versions_dir` (config key in `config/media.php`, default `storage/media-versions`) as `{versions_dir}/{id}/v{n}.{ext}`;
  - never under `public/` or the media dir, which is refused at boot like `private_dir`;
  - served only by the core route `{private_url}/{id}/v/{n}`, gated by `PrivateFileAccess`.
- **Replace:**
  - keeps the id, alt, title, focal point, extra fields, usage, private flag and poster;
  - changes the file, size, width, height, mime, original name, preview, colours and variants;
  - the new file must be the same kind (`Asset::kind()`), else `AssetUploadException`;
  - old public files and their variants are removed after a successful replace;
  - version numbers only grow.
- **Colour:**
  - Conversion to sRGB uses relative colorimetric intent with black-point compensation. Output is stripped, with no embedded profile.
  - The default CMYK profile is shipped in `packages/media/resources/icc/` with its licence file; `config/media.php` `color_profile_cmyk` overrides it.
  - Without Imagick, a CMYK or non-sRGB-profiled source gets no variants, and the asset's `note` is `needs Imagick for colour-accurate variants`.
- **PDF preview:**
  - First page, long side 1600 px (capped by `max_pixels`), sRGB PNG, stored next to the file (`Y/m/{id}[-v{n}]-preview.png`) or in `private_dir` for private assets.
  - Rendering runs with a 30 s limit and only on the asset's own path. A failure leaves `preview` null and the upload succeeds.
- **Colours:**
  - `color` is hex `#rrggbb`, `palette` is 5–8 hex values, most significant first.
  - `text_color` is `#ffffff` or `#000000`, whichever has the higher WCAG contrast on `color`.
  - CSS variables: `--media-color`, `--media-color-rgb`, `--media-text`, `--media-palette-1` … `--media-palette-N`.
  - The class is `media-c-{hash}`. Never inline styles: rules go in one nonce'd head style, deduplicated per page.
- **Extra fields:**
  - `config/media.php` `fields` (model-field shape) and `filters` (names of `select`/`relation`/`boolean` extra fields).
  - A name equal to an own asset key is a boot error naming the field.
- **Gates:**
  - `vendor/bin/phpunit` (baseline v0.34.1: 3087 tests, 99 deprecations; add none);
  - `composer test:mysql`;
  - smeyer.me and smart-stack.works suites;
  - don't touch holz-objekte.org;
  - no merge, push or tag without the owner's go-ahead.

## Review Focus

- **A replace that fails half-way** (disk full, or variant generation dies after the file is written): the asset must still point at a complete file, either the old or the new one. It never points at a missing one, and no version is lost (Task 2).
- **Two replaces of the same asset in quick succession:** version numbers stay unique and both old files end up as versions (Task 2; a lock per asset, as variant generation already uses).
- **A CMYK JPEG on a site without Imagick:** it uploads, gets no variants and the note, and `media_image()` still renders the original with correct dimensions (Task 4).
- **A password-protected or 0-page PDF:** it uploads with no preview and no error, within the time limit (Task 5).
- **`media_color_class()` called for the same asset five times on one page:** one rule in the head, the same class each time (Task 6).
