## Follow-ups (not in 0.27)

- **smeyer.me's config-only login stays unthrottled** (Ruling 9). Throttle, forgot and
  set-password apply only when the default guard has record users, so sites without them see
  no change. Throttling config-only logins too is one condition in `AuthController::staff()`.
  That would be a behaviour change for those sites, so it is a separate decision.
- **PROMOTE minors**, for the final review to fix before the tag or to defer:
  - Timing: an invited account with an empty `password_hash` answers a login faster than an
    unknown address. Fix: hash, then fail, when the stored hash is `''`.
  - A successful login clears the per-client throttle counter too. Fix: clear only the
    e-mail key.
  - When `app.url` is unset, links fall back to `http://localhost`, and those mails carry
    broken links without any warning. Fix: log once, or refuse.
  - `FolioServiceProvider::recordProviders()` catches every Throwable, so a provider build
    error silently turns staff mode off. Fix: use `has()`.
  - `StaffPasswords::setPassword()` saves a stale record, so a password change racing a
    Disable can write `active = true` back. Fix: re-read the record and refuse an inactive
    account before saving (in `PasswordController` too).
- Deferred minors from the task reviews (ledger `progress.md`):
  - the chip `<label title>`;
  - staff e-mail uniqueness is checked by read-then-write (no unique index);
  - the hard-coded English duplicate-e-mail message and the hard-coded page copy (forgot,
    set-password, account);
  - the own-password throttle is keyed per account only;
  - several reset links can be valid at once;
  - a config user with an empty hash is imported silently.
