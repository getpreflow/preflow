# Release 0.71 — preflow/publishing and one record write path Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Drafts, publishing, revisions, scheduling, previews and the full record save/delete path live in a Folio-free package `preflow/publishing` with a public, container-bound API; Folio and sites call it (spec D2, D3).

**Architecture:** `preflow/publishing` (`Preflow\Publishing`) receives the classes of `packages/folio/src/Publishing`, plus `LiveContent` and `RecordDeleter`, and a new `RecordWriter`. Everything they need from Folio becomes a small interface with a plain default in publishing; Folio binds its implementations (catalog, validator, translations, review index, redirects and page cache, save hooks). AdminController, PublishingController, the bulk actions, `FolioTextSource` and confirm-translation call the writer; Folio keeps forms, permissions, flashes and rendering.

**Tech Stack:** PHP 8.4, PHPUnit 11, the Preflow monorepo; the six sites.

**Spec:** `docs/superpowers/specs/2026-11-12-package-audit-fixes-design.md` (D2, D3). Evidence: `.superpowers/audit-2026-11-12/report-folio-src.md` (FOLIO-1), `report-folio-ui-starters.md` (STARTERS-1). The 0.70 leftovers are in `CLAUDE.local.md` ("0.71 leftovers").

## Global Constraints

- Owner's rules: no workarounds; framework = abstractions only; Folio is the UI adapter; mails never mention Folio.
- `packages/publishing/src` contains no `Preflow\Folio\` reference and no user-visible text (messages that reach editors come from the bound implementations). It requires core, data and validation at most (`^0.71 || @dev`, conflict `<0.71` where a 0.71 API is used).
- Moved public classes keep class aliases for one release (`packages/folio/src/legacy-aliases.php`); the renamed commands `folio:publish` and `folio:publish-scheduled` keep working as aliases for one release, printing a deprecation line.
- `config/folio.php` `publishing` keys (`revisions`, `complete_languages`, `preview_ttl`) are read for one release when `config/publishing.php` is missing, with a logged deprecation.
- Stored data keeps its shape: shadow tables, `_version`, `_publish_at`, `_order`, revision rows, preview tokens.
- Whether a type publishes: default reads `TypeRegistry::schema($type)['publishing'] === true`; Folio binds its own, keeping `TypeCatalog.php:195` (explicit flag, else a `frontend` route or a singleton). No site type changes behaviour.
- The six sites behave the same; their code moves to the new names in this release (Task 5).
- Tests per package (`vendor/bin/phpunit --testsuite <Pkg>`); full suite at the release; never two test runs at once; no background test loops left running.

## Review Focus

1. A save by someone who may not publish clears a pending `_publish_at` — through the form, autosave, restore, the bulk set and AI translation, now one rule in `RecordWriter`. → Task 2 test per entry point (Task 3 for the Folio callers).
2. A `#[BeforeSave]` that throws `ValidationException` stops every write path (form, bulk set, reorder, confirm-translation API branch, AI translation) before anything is stored; AfterSave still runs after a failed publish, as today. → Task 2 and Task 3 tests.
3. An AI-translation write on a type with a `#[SaveRecord]` uses that hook instead of `saveType` (release note: AI writes run save hooks). → Task 3 test.
4. A site that still imports `Preflow\Folio\Publishing\Publisher` and builds it with three arguments (`new Publisher($dm, $catalog, $validator)`, holz tests) keeps working for this release. → Task 1 test.
5. The server cron calling `folio:publish-scheduled` keeps publishing due records. → Task 1 test of the alias.

**Interfaces (all in `Preflow\Publishing`, each with a default bound by the provider unless the app binds one):**

- `LanguageChecks`: `clearMachineMarks(DynamicRecord $record): void`; `incomplete(DynamicRecord $record): array<string, list<string>>` (errors keyed `_translations.<locale>`, messages final). - `RecordIndex`: `refresh(DynamicRecord $record): void`; `forget(string $type, string $id): void`. Default: none. Folio: `ReviewIndexUpdater`.
- `RecordAddresses`: `sync(string $type, string $id, ?DynamicRecord $previousLive): bool` (true = an address left the site); `removed(string $type, string $id, ?RemovalTarget $target): void`; `changed(?DynamicRecord $before, ?DynamicRecord $after): void` (page-cache tags). Default: none. Folio: one adapter over its `RecordAddresses`, `PageCache` and `FrontendResolver::addressTags`.
- `RemovalTarget`: marker interface; Folio's `Preflow\Folio\Redirects\RemovalTarget` implements it.
- `Publisher::__construct(DataManager $dm, PublishingTypes $types, RecordChecks $checks, ?int $keepRevisions = 20, ?\Closure $now = null, ?LanguageChecks $languages = null, bool $completeLanguages = false, ?RecordIndex $index = null, ?RecordAddresses $addresses = null)`; public methods unchanged (`enabled`, `snapshot`, `live`, `query`, `state`, `stateWith`, `states`, `saveDraft`, `publish`, `unpublish`, `syncOrder`, `forget`, `discard`, `revisions`, `restore`).
- The Folio alias `Preflow\Folio\Publishing\Publisher` accepts the old 3-argument call `(DataManager, TypeCatalog, RecordValidator)` for this release: a small subclass in `legacy-aliases.php` wrapping the catalog and validator in the Folio adapters (only Publisher needs this; the other classes are plain `class_alias`).
- `Scheduler(Publisher, PublishingTypes, DataManager)`; `PublishedModels(DataManager, LiveContent, ShadowTypes)` (as today, new namespace); `LiveContent(DataManager, PublishingTypes)`.

### Task 2: RecordWriter and RecordDeleter

**Files:** create `packages/publishing/src/RecordWriter.php`, `SaveHooks.php`, `SaveOptions.php`, `SaveOutcome.php`, `RecordTypes.php`; move `packages/folio/src/Content/RecordDeleter.php` (and its `DeletePlan`, `Refused` as needed) → `Preflow\Publishing\…` with a Folio alias.

**Interfaces:**
- `SaveHooks`: `before(DynamicRecord $record): void` (may throw `ValidationException`); `after(DynamicRecord $record): void`; `beforeDelete(DynamicRecord $record): void`; `afterDelete(DynamicRecord $record): void`; `replacesSave(string $type): bool`; `save(DynamicRecord $record, ?DynamicRecord $previous): void`. Default: none. Folio: adapter over `Customizations` (`runHooks`, `hasSaveRecord`, `saveRecord`).
- `RecordTypes`: `orderable(string $type): bool`. Default: false. Folio: `list.orderable` of the listing.
- `SaveOptions(?string $by = null, bool $mayPublish = true, bool $publish = false, ?int $loadedVersion = null, ?string $publishAt = null)` — `$publishAt` null keeps the stored value, `''` clears it, otherwise a `Y-m-d\TH:i` time (a past time is dropped, as `AdminController::publishAt()` does).
- `SaveOutcome(DynamicRecord $record, bool $addressesLeft)`.
- `RecordWriter::create(DynamicRecord $record, SaveOptions $options = new SaveOptions()): SaveOutcome` (assigns `bin2hex(random_bytes(16))` when the id is empty; `_order` = highest + 10 when orderable), `save(DynamicRecord $record, SaveOptions $options = new SaveOptions()): SaveOutcome`, `setField(DynamicRecord $record, string $field, mixed $value, SaveOptions $options = new SaveOptions()): SaveOutcome`, `reorder(string $type, string $id, string $direction): bool` (`'up'|'down'`; false at the edge).
- Save order (from `AdminController::store/update/savePublishing/saveWithBlocks/applySchedule`): before hooks → schedule rule (`!$mayPublish` clears `_publish_at`; else apply `$publishAt`) → publishing type: `saveDraft`, then `publish` when `$options->publish` (after hooks run also when publish throws, then rethrow) → other types: checks, `SaveHooks::save` when `replacesSave` else `saveType($record, false)`, index refresh, address sync, after hooks.
- `reorder` swaps `_order` of the two neighbours, saves each through the hooks (before/after, `replacesSave`) without content checks, then `Publisher::syncOrder`.
- `RecordDeleter(DataManager, PublishingTypes, ?Publisher, ?SaveHooks, ?RecordIndex, ?RecordAddresses, …)`: `plan()`, `delete()`, `MAX_IDS` unchanged; display texts (`summary()`) stay in Folio (`Preflow\Folio\Content\DeleteSummary`), the deleter returns data only.

- [ ] Tests first, without Folio: each order step above with recording stubs; Review Focus 1 and 2 at the writer level; create assigns id and order; reorder at the edges; a `ValidationException` from `before` stores nothing; delete runs beforeDelete/afterDelete and forgets snapshot, index and addresses.
- [ ] Implement; `--testsuite Publishing`.
- [ ] Commit `feat(publishing): RecordWriter and RecordDeleter, the one record write path`.
