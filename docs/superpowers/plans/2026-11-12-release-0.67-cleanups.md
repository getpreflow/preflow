# Release 0.67 — boundary clean-ups Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** No package names another package's keys, files or classes, and no package carries a site's wording (spec D8).

**Architecture:** core keeps each installed package's whole composer `extra` and lets packages declare their own runtime-checked files; view gets an image-source interface that media binds; data forgets Folio's matrix keys; small renames and neutral examples elsewhere. Then the preflow.dev docs follow.

**Tech Stack:** PHP 8.4, PHPUnit 11, the Preflow monorepo (`packages/*`), the website repo `/Users/smyr/Sites/gbits/preflow-website`.

**Spec:** `docs/superpowers/specs/2026-11-12-package-audit-fixes-design.md` (D8). Evidence: `.superpowers/audit-2026-11-12/report-*.md` (CORE-1, VIEW-1, DATA-1, MEDIA-1, I18N-1, DEVTOOLS-1, CODES-2).

## Global Constraints

- Owner's rules: no workarounds; the framework holds abstractions only; Folio is the UI adapter.
- No package may name another package's classes, composer keys or files; it defines an interface or a registration hook instead.
- No site name or site wording in code, docblocks, READMEs or config examples (smart-stack, BG Genius, holz-objekte, languagecorner, smeyer; GameCard, WoodObject, Meeple, Cascadia, /spiele/, Game Club, Force Map). Example domain everywhere: the starters' job board (jobs, companies, `/jobs/…`, "Job Board").
- Existing composer keys keep working unchanged: `extra.preflow.translations`, `extra.folio.extension`, `extra.folio.field_types`, `extra.folio.blocks`.
- Tests: the package's own suite per task; the full suite (`vendor/bin/phpunit` at the repo root, ~12 min, in the background) only at the end; never two test runs at once.
- No subagents inside tasks. Commit per task with a conventional message.
