# Release 0.34 checklist

New package `preflow/media`: the asset library moved out of Folio into a core of its own
(`MediaLibrary`, `Asset`, `Variant`, `ImageTag`, image backends, usage sources, private-file
and variant routes, `media_image()`/`media_url()`, `media:variants`). Folio is only the UI
adapter: library screen, asset field, and its rules bound to the core's hooks. The work is on
`feat/media-package`. The release is prepared: media README, Folio README (UI and
deprecations), roadmap entry, spec. It is not merged, pushed or tagged; the owner decides.
Constraints: media requires `preflow/core`, `preflow/data`, `preflow/view` at `^0.34 || @dev`
(conflict `<0.34`), plus `preflow/routing` and `nyholm/psr7`, and suggests `preflow/i18n`;
folio requires `preflow/media ^0.34 || @dev` and `preflow/core ^0.34 || @dev` and conflicts with
`<0.34`.

## Upgrading to 0.34: notes for site owners

Also in the media README and the Folio README (Asset library). Put these in the release notes.

- **Renames** (the old names keep working for one release as aliases from
  `packages/folio/src/legacy-aliases.php`, the old template functions and command too):

  | Old | New |
  |---|---|
  | `Preflow\Folio\Assets\Asset`, `Variant`, `AssetUploadException`, `ImageTag`, `ImageWidths`, `VariantGenerator` | `Preflow\Media\…` (same short names; `ImageWidths` and `VariantGenerator` under `Preflow\Media\Image\`) |
  | `Preflow\Folio\Assets\Image\{ImageBackend, ImageBackends, GdBackend, ImagickBackend, Orientation}` | `Preflow\Media\Image\…` |
  | `Preflow\Folio\Assets\AssetLibrary` | `Preflow\Media\MediaLibrary` |
  | `folio_image()` | `media_image()` |
  | `folio_asset_url()` | `media_url()` |
  | `config/folio.php` `assets` (library settings) | `config/media.php` |
  | `php preflow folio:assets:variants` | `php preflow media:variants` |

- **`config/media.php`** takes the library settings (`dir`, `url`, `storage`, `max_bytes`,
  `max_pixels`, `warm_on_upload`, `allow_svg`, `widths`, `quality`, `private_dir`,
  `private_url`). It is read first; `config/folio.php` `assets` is read only when
  `config/media.php` is missing (and logged as a deprecation). The two are never merged: a
  leftover `assets` block next to a `media.php` is ignored.
- **Private settings stay in `config/folio.php`:** `assets.private_permission` (default
  `folio.dashboard`) and `assets.private_login` are Folio's rule for who may download private
  files. Without a `PrivateFileAccess` bound, the core denies private files with a 403. A
  site's own `PrivateFileAccess` must come from a provider listed after
  `FolioServiceProvider` in `config/providers.php`.
- **`AssetReferences` stays in Folio** (not deprecated; holz-objekte.org uses it).
- **Usage sources:** the core registers `PosterReferences`, Folio its record source. A site that
  stores asset references registers an `AssetReferenceSource` with `AssetUsage`, or its
  references do not block deleting.
- **The core now refuses to delete used assets:** `MediaLibrary::delete()` throws
  `AssetInUseException` (with the usage listed). `discard()` exists only for an asset created
  in the same request.
- **Storage and output are unchanged:** `folio_assets` table, `public/media/Y/m/{id}.{ext}`,
  `storage/private-media`, `/media/…`, `/files/{id}`, and the frontend HTML (including
  `folio-focal`, `folio-fx-*` and `folio-fy-*`).
- **Without Folio:** list `Preflow\Media\MediaServiceProvider` in `config/providers.php`. With
  SQL storage `preflow migrate` creates the asset table (`media.table` step).
- **Core:** `Container::registerProvider()` ignores a second registration of the same
  provider class (Folio registers media whether or not the app lists it); `hasProvider()` and
  `bound()` are new; `DebugCollector::logDeprecation()`.
- A site that type-hints `AssetLibrary` keeps working through the alias (same class, no binding).
