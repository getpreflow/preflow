# Release 0.74 — Run the SEO audit from Folio Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An editor with the right permission starts, continues and restarts the SEO audit from Settings → SEO audit in Folio; the page runs it in short steps and shows progress until the report is complete.

**Architecture:** The audit already runs in budgeted, resumable batches (`Preflow\View\Audit\AuditRun`, one full run at a time via a lock, `AuditRunning` otherwise) and renders pages anonymously through `PageRenderer` (bound lazily in web requests too, `Application::bootAudit`). preflow/view gets one public service that runs one step of the saved audit; `seo:audit` and Folio both use it. Folio adds the routes, the permission and the screen, following the AI translate run screen's step-and-poll pattern (`AiTranslateController::start/step`, `templates/admin/ai/run-progress.twig`).

**Tech Stack:** PHP 8.4, PHPUnit 11, Twig, htmx (already in Folio), `admin.js` busy buttons from 0.73.

**Spec:** owner, 2026-11-13: "can we make it so the seo audit can be triggered from within folio?" — agreed answer (chat): Run audit button + Start over, the page runs ~20 s steps with progress ("37/120 pages") until done, closing the page pauses it and the next click continues; a separate permission to run it; mail never sent from an audit render; steps stay well under the host's time limit; CLI and Folio runs never collide.

## Global Constraints

- Framework = abstractions; Folio is only the UI adapter (the step logic lives in preflow/view, Folio only calls it).
- Mails never mention Folio; no new mail here.
- New UI text in `packages/folio/lang/en|de|fr/folio.php` (all three); 0.73's redesign primitives (`.btn`, `data-busy-label`, `.folio-alert-*`, subtitle) for the new UI.
- One step's time budget: 20 s (constant in the Folio controller); the command keeps its 600 s default.
- Tests one run at a time: `vendor/bin/phpunit --testsuite View`, `--testsuite Folio`, `node --test packages/folio/tests/js/*.test.mjs`, `composer test:starters`.
- Existing `seo:audit` behaviour and output unchanged (its tests stay green unmodified).

## Review Focus

1. A web step renders pages inside an admin request: the renders stay anonymous (no admin cookie/session/auth leaks into a page; a members-only page audits as the visitor sees it) and leave the outer request's state (locale, SEO context, assets, current user) as it was. → Task 2 test: step as a signed-in admin over a page that shows the user's name; the finding/HTML has no name, and the admin response after the step still has the admin's locale.
2. Mail queued while an audited page renders is never sent from a web step (the CLI relies on not sending it). → Task 1 test with a page that queues a mail.
3. A CLI run holding the lock while someone presses Run in Folio: Folio says "an audit is running elsewhere" and polls/offers retry; no exception page, no second run. → Task 2 test.
4. The step request on a host with a short `max_execution_time`: the budget (20 s) plus one slow page must not hit a 30 s limit; raise the limit like `AiTranslateController::allowLongRequest` where allowed. → Task 2 test that the step calls the budget with 20.
5. A user with `seo.audit` (view) but not the new run permission sees the report without the buttons and gets 403 on the POST routes; CSRF is required. → Task 2 tests.

### Task 1: preflow/view — the audit step service

**Files:** create `packages/view/src/Audit/Audits.php`; modify `packages/core/src/Application.php` (bind it next to the PageRenderer in `bootAudit`), `packages/view/src/Console/SeoAuditCommand.php` (build the run through the service); test `packages/view/tests/Audit/AuditsTest.php`.

**Interfaces — Produces:**
- `final class Preflow\View\Audit\Audits` (container singleton, @since 0.74)
  - `step(int $timeBudgetSeconds, bool $fresh = false, ?\Closure $progress = null): AuditReport` — one budgeted step of the saved full audit (`AuditRun::run($budget, null, null, $fresh, $progress)`); throws `AuditRunning`.
  - `quick(?int $limit, ?string $url, int $timeBudgetSeconds, ?\Closure $progress = null): AuditReport` — the command's quick checks.
  - `report(): ?AuditReport` — the saved report (`AuditReport::load`).
  - `running(): bool` — whether another full run holds the lock right now (non-blocking probe of the same lock file; never blocks, never takes it for longer than the probe).
  - `file(): string` — the report file.

### Task 2: Folio — run the audit from Settings → SEO audit

**Files:** `packages/folio/src/Http/SeoAuditController.php`, `packages/folio/src/Routing/FolioRoutes.php`, `packages/folio/src/FolioServiceProvider.php` (controller wiring, permission declare), `packages/folio/templates/admin/seo-audit/index.twig` and a new `_progress.twig`, lang en/de/fr, tests `packages/folio/tests/Http/SeoAuditControllerTest.php` (extend) and a template test.

**Interfaces — Consumes:** `Audits` from Task 1.

- Permission `seo.audit.run` declared ("Run the SEO audit", Folio), next to `seo.audit`; the routes need `seo.audit` (FolioPermissionMiddleware) and the controller checks `seo.audit.run`. How existing roles get new permissions: follow what the RBAC package does for a newly declared permission (admins/superuser get it; nothing else changes).
- Routes: `POST {prefix}/seo-audit/run` (body `fresh=1` optional) → runs the first step and returns the page with the progress partial; `POST {prefix}/seo-audit/step` (htmx) → one 20 s step, returns `_progress.twig`, which re-triggers itself (`hx-trigger="load"`, CSRF as the AI run progress does) until the report is complete, then swaps to (or redirects to) the finished report. Without JS: Run posts, the page shows progress with a "Continue" button (plain POST) — each press runs one step.
- States on the screen: no report yet (Run audit); incomplete (Continue + Start over, "n of m pages"); complete (Run again = fresh); running elsewhere (`running()` true or `AuditRunning` caught: notice + the step partial polls every 10 s without running, or a Retry button); a step that fails (alert-error with the message, Continue offered). The subtitle keeps the existing intro; the old "run `preflow seo:audit`" hint stays as secondary text (the command still works).
- Long request: raise the time limit as `AiTranslateController::allowLongRequest` does (a limit below 60 s → 60).
- Tests (Review Focus 1, 3, 4, 5): run/step as admin with the right permission; without `seo.audit.run` → 403 and no buttons; CSRF missing → refused; step while another lock is held → running-elsewhere state, 200; step completes → finished report; renders anonymous (a page printing the current user shows no user) and the admin's locale unchanged after the step; the step budget is 20.
