# SEO basics Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Share cards, JSON-LD, robots meta, generated robots.txt / sitemap.xml / security.txt, theme-color and ETag/304 for Preflow sites, opt-in through `config/seo.php`, with a per-record "SEO & sharing" section in Folio and one public-pages list shared with GEO.

**Architecture:** Mechanism in `preflow/view` (`src/Seo/`, next to `src/Geo/`): config, value objects, head-tag renderer, JSON-LD, public-pages registry, the generated files and one `SeoMiddleware` that serves them, injects head tags into HTML responses and answers 304s. `preflow/folio` adapts it: the editor section (stored as reserved meta `_seo`, published like content), the Folio source of public pages (replacing `FolioGeoEntries`), and per-record page meta resolved in `FrontendController`. `preflow/media` gains JPEG box variants and a built-in `share` preset. `preflow/core` wires it in `bootSeo()`, before `bootGeo()` so GEO stays outermost.

**Tech Stack:** PHP 8.5, PHPUnit 11, Twig 3 / Blade, PSR-7/15 (nyholm), `Dom\HTMLDocument` not needed (head edits are string inserts before `</head>`).

**Spec:** `docs/superpowers/specs/2026-11-01-seo-design.md`

## Global Constraints

- Off by default: no `config/seo.php` or `'enabled' => false` → no tag, header, route, admin section or behaviour change (byte-identical HTML).
- Mechanism in packages, site wording/data in sites; Folio is the UI adapter; domain schemas (JobPosting, Product, Game…) are not shipped.
- The framework adds only tags the page doesn't already have (no duplicate description/robots/og/canonical).
- Never: members-only/gated (`frontend.permission`), preview, noindex pages in sitemap, llms.txt, cards or JSON-LD; never a 304/ETag for a response that is `private`/`no-store` or sets a cookie (PSR header **or** native `headers_list()`), or to a request carrying a session cookie.
- `<title>` and `<meta name="description">` stay the layouts' job.
- Strict CSP stays intact; JSON-LD is data (`application/ld+json`), escaped with `JSON_HEX_TAG | JSON_HEX_AMP | JSON_HEX_APOS | JSON_HEX_QUOT`.
- English UI strings plus German (du) translations for every new Folio string.
- Full framework suite green (`php vendor/bin/phpunit`, ~10 min: run in background or with a 600000 ms timeout).
- Release as 0.50.0 (not part of this plan's tasks; the controller does it after the final review, with owner approval).

## Review Focus

1. A page template that already prints `og:title`, `<meta name="robots">` or JSON-LD → the framework adds none of that kind (Task 2 test `test_existing_tags_are_not_duplicated`).
2. User content with `</script>`, quotes, `&` or HTML in titles/descriptions → valid JSON-LD and attributes, plain text (Task 2 `test_hostile_text_is_escaped`).
3. Two requests for the same page get different CSP nonces → same ETag; `If-None-Match` → 304 (Task 4 `test_etag_ignores_the_nonce`).
4. A signed-in visitor (session cookie on the request, or a session started during the response) → no ETag, never 304 (Task 4 `test_no_etag_for_personal_responses`).
5. A draft change to `_seo` (e.g. noindex ticked, not yet published) → live page, sitemap and cards unchanged; the share preview shows it (Task 6 `test_seo_changes_take_effect_on_publish`).
6. A share image asset that is missing, deleted, private or not an image → no `og:image`, no error (Task 6 `test_unusable_share_image_is_skipped`).
7. A site without a `site` singleton or without Folio → defaults from config, no errors (Task 4 `test_works_without_folio`).
