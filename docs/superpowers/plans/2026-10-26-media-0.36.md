# Media 0.36 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The 0.36 half of media release 2: formats with fixed boxes, non-destructive crop, rotate and flip, per-format crops (art direction), and Folio's image editor. All of it is in the `preflow/media` core, and Folio only adds UI. Released as v0.36.0.

**Architecture:**
- **Edit state:** an asset's edits (`rotation`, `flip`, `crop`, `crops`) are columns of the asset record. The original file is never written over.
- **Rendered master:** an edited image gets a *rendered master*, which is the original with rotation, flip and image crop applied, stored beside it. The new `MediaLibrary::deliveryAsset()` returns the image a page shows: the master, the untouched original, or a document's preview. Variants, colours and URLs are made from it.
- **Box presets:** these are presets with `height` and `fit`. They render through a `BoxPlan` that the core computes from the delivery image, the focal point or format crop, and the preset. The plan's file names carry a render key, so any change makes new URLs.
- **Folio:** an *Edit image* screen calls the core API, with a vendored Cropper.js for the crop rectangles.

**Tech Stack:** PHP 8.4, PHPUnit 11, GD, Imagick (ImageMagick 7 with lcms), Twig, Cropper.js 1.6.2 (vendored).

**Spec:** `docs/superpowers/specs/2026-10-25-media-release-2-design.md`. Read "Design — 0.36", "Settled details" and "Tests (for the builder)", which bind. 0.35 is released (v0.35.0); its code is the base.

## Global Constraints

- **Owner's rule:** every capability is in `packages/media/src`, with no `Preflow\Folio` there (`NoFolioDependencyTest` stays green). Folio only adds UI and calls the core.
- **Nothing changes for untouched assets and width-only presets:**
  - release 1's byte-identical fixture (`packages/folio/tests/Integration/AssetFrontendTest.php`) stays green and unchanged;
  - existing records read as unedited (`rotation` 0, no flip, no crops, no master);
  - presets without `height` behave as today (`fit` defaults to `max`).
- **File names** (`{stem}` is the current file's stem, `Y/m/{id}` or `Y/m/{id}-v{n}`):
  - rendered master: `{stem}-edit-{key}.{ext}`; its variants: `{stem}-edit-{key}-{w}.{fmt}`;
  - box variants: `{delivery stem}-{preset}-{key}-{w}.{fmt}`. Example: `2026/10/{id}-v3-cover-thumb-1a2b3c4d-400.webp`, or `2026/10/{id}-edit-9f8e7d6c-cover-thumb-1a2b3c4d-400.webp` for an edited one;
  - editor image (Task 3): `{stem}-oriented-{key}.webp`;
  - `{key}` is the first 8 hex characters of `sha256` over the JSON of the inputs listed in Task 1.
- **Reserved names:** box preset names match `^[a-z][a-z0-9-]*$` and are not `edit`, `preview` or `oriented`; anything else is a boot error naming `config/image.php` and the preset.
- **Coordinates:**
  - `CropRect` values (image crop and format crops) are in percent of the **rotated and flipped original**, clamped to the image;
  - the focal point is in percent of the **delivery image** (the master when edited), so the panel's focal click and `object-position` keep their meaning.
- **Transform order:** EXIF upright, then mirror (when `flip`), then rotate clockwise by `rotation` quarter turns, then the image crop. The result is the master. A box variant then takes the format crop, or the focal-point box, out of the master.
- **Never upscale:** box and master variants are never wider than their source region.
- **Colour:** the master and box variants are sRGB and stripped. A source that needs colour management goes through Imagick (`VariantGenerator::backendFor()`). Without Imagick such a source gets no master, and the asset gets the existing note `needs Imagick for colour-accurate variants`.
- **Gates:**
  - `vendor/bin/phpunit` (baseline v0.35.0: 3276 tests, 99 deprecations; add none);
  - `composer test:mysql`;
  - smeyer.me and smart-stack.works suites;
  - don't touch holz-objekte.org;
  - no merge, push or tag without the owner's go-ahead.

## Rulings made in this plan (for the owner to check)

1. **Edits are for public JPEG, PNG, WebP and AVIF images only.** Private images, GIF and SVG are refused with `\InvalidArgumentException`. Private images have no variants or formats today, and their master would need its own gated route.
2. **`width`/`height` stay the original's.** The master's size is in `master` (`Preview` shape: path, width, height), and `deliveryAsset()` reports it. The spec says "the asset reports the master's size, the original's kept separately". This keeps that meaning for pages, without touching the replace and version code that reads `width`.
3. **Rotation clears per-format crops,** because their fixed ratio no longer fits after a quarter turn. Mirroring mirrors them. The image crop and the focal point follow both, so the same part of the picture stays selected.
4. **A format crop stands on its own** (in rotated-original percent, independent of the image crop), cut to the box ratio around its centre. That is what art direction is for.
5. **Box variants are made on first request,** like step widths, and by `media:variants --all` and `warm_on_upload`. They are not made at upload, which keeps uploads fast.
6. **Any edit or focal-point change deletes all box files of the asset.** Files whose key didn't change are simply made again on the next request.
7. **The master keeps the original's format** (AVIF becomes WebP), at quality 92.
8. **`contain` reports its fitted size** (inside the box, the image's own ratio) as `width`/`height`, not the box size, so the picture is never distorted.
9. **Box presets' `widths` don't join the width-only allow-list** (`ImageWidths`). They are box widths, not full-image widths.
10. **The editor is its own screen** (`{prefix}/assets/{id}/edit`), opened by an *Edit image* button in the details panel. Rotate and mirror run on the server (no client-side rotation). Cropping needs JavaScript; rotate, mirror and reset don't.

## Review Focus

- **Replacing an edited image with one of a different shape:**
  - rotation, flip and the percent crops stay;
  - the master is made again from the new file, under new URLs;
  - the old master, its variants and the box files are gone;
  - no URL on the page is a 404 (Task 3).
- **An image smaller than a box** (150×150 with a 200×200 box, 2× = 400):
  - it is never upscaled, and the srcset lists only 150;
  - `width`/`height` are still 200×200 for the layout (Task 4).
- **A phone JPEG with EXIF orientation 6, then a quarter turn:** the rotation applies on top of the upright image. Pixel test: the expected corner colour is top-left (Task 2).
- **Undoing every edit** (four quarter turns, crop cleared):
  - the asset delivers the original again under today's names (`{id}-480.webp`) and today's HTML;
  - the master files are gone (Task 3).
- **Editing a CMYK JPEG without Imagick:** the edit is saved, but no master is made. The asset shows the note, and the page keeps showing the original rather than wrong colours (Task 3).

**Interfaces — Produces:**
- **`final readonly class CropRect(float $x, float $y, float $width, float $height)`**, in percent:
  - `static of(float $x, float $y, float $width, float $height): self` clamps: width and height to [1, 100], x to [0, 100 − width], y to [0, 100 − height], each rounded to 2 decimals;
  - `toArray(): array{x, y, width, height}` and `static fromArray(mixed): ?self` (null for anything malformed);

  - `mirrored(bool $horizontal): self`: horizontal gives (100 − x − w, y, w, h), vertical gives (x, 100 − y − h, w, h);

- **`Asset` properties**, named constructor arguments with defaults at the end:
  - `int $rotation = 0` (quarter turns clockwise, 0–3; column `rotation`);

- **`final readonly class Format(string $name, int $width, ?int $height, string $fit, list<int> $widths)`**:
  - `isBox(): bool` is true for `cover`/`contain`;
  - `ratio(): ?float`.
- **`final class Formats`**:
  - `static fromConfig(array $presets): self` reads `config/image.php` presets. `fit` defaults to `max`. It throws `\InvalidArgumentException` naming `config/image.php` and the preset for:
    - a `fit` other than `cover`, `contain` or `max`;
    - a box without a positive `width` and `height`;
    - a box name outside the reserved-name rule;
  - `get(string $name): ?Format`;
  - `boxes(): array<string, Format>`.
- **`final class Geometry`**, static and pure:
  - `focalBox(int $srcW, int $srcH, float $ratio, int $focalX, int $focalY): array{x, y, w, h}`: the largest rectangle of `$ratio` inside the source, centred on the focal point (percent of the source), clamped to the edges;
  - `fitRatio(array $region, float $ratio): array{x, y, w, h}`: the largest rectangle of `$ratio` inside `$region`, centred in it;
  - `containSize(int $srcW, int $srcH, int $boxW, int $boxH): array{int, int}`: the size that fits the box, never larger than the source;
  - `focalAfter(int $focalX, int $focalY, ?CropRect $from, ?CropRect $to): array{int, int}`: carries a focal point (percent of the old crop) to percent of the new crop, keeping the same picture point. It is clamped to 0–100 and rounded.
- **Render keys** (`Formats::key(array $inputs): string`, the first 8 hex characters of sha256 of `json_encode($inputs)`):
  - master inputs: `[version, rotation, mirrored, crop?->toArray()]`;
  - box inputs: `[delivery stem, format name, width, height, fit, widths, region x, y, w, h]`.

**Interfaces:**
- Consumes: Tasks 1–3.
- Produces:
  - **`final readonly class BoxPlan(Format $format, Asset $source, string $base, int $width, int $height, list<int> $widths, array $crop)`:**
