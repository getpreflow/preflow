## Global Constraints

- **Guide rhythm (enforced by a test from Task 1 on):** six `##` sections in this order: `In one sentence`, `See it work`, `How it ties in`, `Step by step`, `Good to know`, `Go deeper`. At least one code example (a ```starter``` fence or a code block) and at least one figure (```figure``` or ```diagram```). "Go deeper" links the guide's reference topic page (`/docs/reference/topics/<key>`), the most important reference entries used on the page, the next guide, and (where one exists) how to extend it (`/docs/extend/...` — pending pages may be linked as plain text until phase 3).
- **Truth:** every statement true for Preflow 0.63.1 — verified against `/Users/smyr/Sites/gbits/preflow-framework/packages/<pkg>/README.md` and the code (read-only). Code shown from the starters only through the ```starter``` fence (sync new files via `config/starters.php` + `php preflow starters:sync`); code the reader writes must follow the starters' conventions and be correct (run it in a fresh starter when it's more than a few lines).
- **Completeness:** each guide covers its topic's members in `topics.php` well enough that a reader knows what exists and when to use it — the guide explains the common path in depth and points to the reference for the rest. Nothing in the topic is left unmentioned without at least a pointer.
- **Voice:** as in `docs/understand/*` and `docs/start/*` — plain, friendly, short sentences, concrete; glossary terms linked on first use (`/docs/understand/glossary#…`; add a glossary entry when a new term needs one); inline per-section "Go deeper:" lines are allowed in addition to the final section.
- **Old pages:** when a guide replaces an old page (`docs/guides/*`, `docs/packages/*`), delete the old file, remove it from "Older pages", and add a 301 (seeded like the getting-started redirects in `ContentSeeder::redirects()`, also applied on already-seeded sites).
- Strict CSP, cookie-free, both themes, 375 px; never two test suites at once; commit locally only.

## Review Focus

1. A claim that's true for one package version or config but stated as always true (defaults vs. options).
2. A guide that explains only the happy path of its topic and silently leaves out half of the topic's members.
3. Code the reader types that wouldn't run (wrong namespace, missing `use`, wrong config file).
4. A diagram that contradicts the text or the code.
5. Broken links/anchors after redirects (the link test from phase 1 must cover every new page).
