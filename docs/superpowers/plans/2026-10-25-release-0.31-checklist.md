# Release 0.31 checklist

CSRF on an expired session (preflow/core): `CsrfMiddleware` tells a POST whose session
expired from other CSRF failures (`CsrfSessionExpiredException`, still a 403) and offers an
opt-in `ExpiredSessionHandler` that a site binds in the container to answer that case before
the app runs. Asked for by holz-objekte.org (`docs/framework-followups.md` "A POST after the
session expired"), whose `App\Http\WizardSessionExpiry` replaces the `CsrfMiddleware` in the
pipeline by reflection today. The work is on `main` (owner's go-ahead 2026-10-25). Core README
("CSRF") and the roadmap entry are updated. No new package, so no new split repository, and
no constraint change (no other package uses the new API).

## The API

- `Preflow\Core\Http\Csrf\CsrfSessionExpiredException extends ForbiddenHttpException`
  (403, `CSRF token mismatch: session expired.`): the session held no CSRF token before the
  request (`CsrfToken::fromSession()` null, checked before `generate()`) and the request
  carried a non-empty one (`_csrf_token` field or `X-CSRF-Token` header).
- Every other failure (wrong token on a live session, no token) stays
  `ForbiddenHttpException('CSRF token mismatch.')`.
- `Preflow\Core\Http\Csrf\ExpiredSessionHandler::handle(ServerRequestInterface): ?ResponseInterface`.
  Bind it in a service provider:
  `$container->singleton(ExpiredSessionHandler::class, MyHandler::class);`. Called for the
  expired case only, with the new session and its fresh `CsrfToken` as request attributes; a
  response is sent (the app is not called), `null` gives the 403.
- `new CsrfMiddleware(array $exempt = ['/--component/'], ?ExpiredSessionHandler $expiredSessionHandler = null)`.
  The Application passes `ContainerExpiredSessionHandler` (internal), which looks the binding
  up per expired request: the middleware is built before the providers run.
- Security rule (README): never apply posted data from an expired-session request; at most
  keep it to prefill the form after sign-in. Limit the handler to own paths and same-origin.

## Upgrading from 0.27 to 0.31 — notes for site owners

Put these in the release notes. Details in the 0.28, 0.29 and 0.30 checklists.

- **0.27.1 (htmx):** guarded components authorize plain `render` requests too (a signed
  render token no longer re-renders a component the guard refuses); fragment `<style>` tags
  get the page nonce.
- **0.28 (data):** JSON-stored types cache queries under `storage/cache/data` (writable,
  git-ignored; unwritable means uncached). `Field::searchable` and the type's `searchable` are
  nullable; `search()` is unchanged. `preflow/core` conflicts with `preflow/data` `<0.28`:
  update all `preflow/*` packages together.
- **0.29 (Folio lists):** lists without `list.sort` / `orderable` now end in record-id order
  (on SQLite this replaces insertion order). `onDelete: detach` is the default: deleting a
  record rewrites the records pointing at it (hooks run). List markup gained a tick column
  (`folio-bulk-cell`) and sortable headers: tests reading cells by position need updating;
  overrides of `@folio/admin/list.twig` use `row.cells` / `row.marked`. Hidden fields are
  not loose-searched unless `"searchable": true`; a hidden field in `list.filters` fails at
  boot; labels never use a hidden field. Excel export needs `openspout/openspout`.
  `JsonFileDriver` refuses ids and types holding `/`, `\`, NUL, `.` or `..` (save/delete
  throw `InvalidArgumentException`, reads find nothing).
- **0.30 (Folio screen assets):** an extension's `assets/` is served (whitelisted types
  only; no PHP in `assets/`, discovery scans it); `assets:` on screens and panels; a listed
  file that is missing throws an `ExtensionException`. Extension pages stay under the strict
  CSP.
- **0.31 (core CSRF):** no change needed. An expired-session POST still answers 403, now as
  `CsrfSessionExpiredException` (a `ForbiddenHttpException`; message
  `CSRF token mismatch: session expired.`). Code or tests that compare the exact message of
  that case need updating. Optional: bind an `ExpiredSessionHandler`.
- After `composer update 'preflow/*'`, delete `storage/cache/folio-extensions.cache` and run
  the suite.
