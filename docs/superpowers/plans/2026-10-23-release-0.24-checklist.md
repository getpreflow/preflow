# Release 0.24 checklist

Every step is gated by the user. The 0.24 work is on `feat/notify-defer`; the release is
prepared (roadmap entry, README) but not merged, pushed or tagged.

1. **Merge.** Merge `feat/notify-defer` into `main` locally (the sites symlink the
   packages, so run all site suites first: smeyer.me, preflow.dev and smart-stack.works,
   wherever they exist).
2. **Push `main`.**
3. **Tag** `v0.24.0` with the message
   `v0.24.0: Notifier::sendLater sends mails after the response`,
   and push the tag. CI splits the packages.
4. **Packagist.** No new packages this release, so the CI ping updates all of them.
   **Constraints.** No package's `require` list changes: no package uses `sendLater` yet.
   Only sites that call it raise their constraints on `preflow/core` and `preflow/notify`
   to `^0.24 || @dev`.
   **Preflight (after the tag is on Packagist, before deploying):** in a temp copy of
   smart-stack.works run `php deploy/server-composer.php`, then
   `composer update "preflow/*" --no-dev` against Packagist, then the site suite.
   No migrations come with 0.24.
5. **Sites.** Sites move to `^0.24 || @dev` when they switch account-flow mails to `sendLater`.

## For sites adopting 0.24

- `$notifier->sendLater($message, $onFailure)` queues; core sends after the response
  (`fastcgi_finish_request()` under PHP-FPM). Use it on forgot-password, registration and
  resend-confirmation so response time does not reveal whether an account exists.
- Deferred failures never throw; give `$onFailure` or bind a PSR logger.
- Needs both `preflow/core` and `preflow/notify` at 0.24 (core does the flush).
- `'defer' => false` in `config/notify.php` sends at once. Nothing else changes.
